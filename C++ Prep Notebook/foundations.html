1. Machine code: computer actually kya samajhta hai?

CPU sirf 0 aur 1 samajhta hai. Har CPU ke paas kuch fixed instructions hoti hain, jaise "do numbers jodo", "memory se value lao", "is address pe jump karo". In instructions ki list ko Instruction Set kehte hain.

  • Machine code = wo binary instructions jo CPU seedha chala sakta hai, bina kisi translator ke.
  • Assembly = machine code ka human-readable roop (add eax, ebx). 1 assembly line ≈ 1 machine instruction.
  • Har CPU family ka instruction set alag hai: x86-64 (Intel/AMD laptops), ARM (mobiles, Apple M-series). x86 ka machine code ARM pe nahi chalega. Ye baat portability mein kaam aayegi.

Insaan binary mein bada software nahi likh sakta, isliye high-level languages bani. High-level code machine code kaise banta hai, iske 3 tareeke hain:

TareekaKaiseExample
CompilerPehle poora code ek baar machine code mein, phir directly chalaoC, C++
InterpreterLine-by-line padho aur saath-saath chalaoPython (roughly)
VM (bytecode)Pehle beech wali language (bytecode), phir ek software (VM) usse chalata haiJava, C#

Interview one-liner

"C++ program 4 stages se guzarta hai: preprocessing, compilation, assembly aur linking. Result ek native executable hai jo OS loader memory mein daalta hai aur CPU directly chalata hai. Syntax/type galti compile time pe pakdi jaati hai, missing definitions link time pe."

4. "Close to hardware" ka matlab

C++ code aur CPU ke beech koi extra layer nahi hai. Teen concrete reasons:

  1. Directly machine code: chalte waqt koi interpreter ya VM beech mein nahi.
  2. Pointers = asli memory addresses: int* p = &x; mein p mein RAM ka actual address hai. Memory byte-by-byte padh/likh sakte ho. Hardware drivers isi se device registers control karte hain.
  3. Types hardware se map hote hain: int ek CPU register mein fit, a + b lagbhag ek add instruction. Object ka memory layout bhi tum control karte ho (padding).

Python mein a + b likho toh runtime pe check hota hai a ka type kya hai, b ka kya, kaunsa + chalana hai. C++ mein ye sab compile time pe decide ho chuka hai.

5. VM, JVM aur javac

VM (Virtual Machine) yahan matlab process VM: ek software jo "nakli CPU" ki tarah behave karta hai.

  • javac = Java ka compiler (java + compiler). Machine code nahi, bytecode banata hai.
  • Bytecode = ek universal instruction set, kisi real CPU ka nahi, sirf JVM ka.
  • JVM har platform ke liye alag bana hai, par sab same bytecode chalate hain.
  • JIT (Just-In-Time) compiler: jo code baar-baar chalta hai, JVM use run time pe machine code bana deta hai.
  • JVM Garbage Collector bhi chalata hai.

7. Portability: source vs binary

Binary (.exe, a.out) do cheezon se bandha hai:

  1. CPU: x86 ka machine code ARM pe nahi chalega.
  2. OS: executable formats alag (Windows = PE, Linux = ELF, Mac = Mach-O), aur OS se baat karne ke tareeke (system calls) bhi alag.
Source portable?Binary portable?
C++✅ Same .cpp har OS pe compile ho jaati hai (standard C++ use kiya ho toh)❌ Har platform ke liye alag compile
Java✅✅ "Write once, run anywhere": .class kisi bhi JVM pe
Depth point: hidden portability trap

Standard sirf minimum size batata hai, exact nahi. long 64-bit Linux pe 8 bytes hai par 64-bit Windows pe 4 bytes. Exact size chahiye toh int32_t, int64_t (<cstdint>) use karo.

Control ki keemat: 3 classic bugs

  • Memory leak: new kiya, delete bhool gaye.
  • Dangling pointer: delete ho chuki / scope se bahar memory use ki (Set 2 Q8: local ka address return).
  • Double free: same memory do baar delete (Top30 Q10: shallow copy).

Java mein ye bugs (mostly) nahi hote kyunki GC hai. C++ ka jawab GC nahi, RAII hai.

9. Zero-overhead principle

Stroustrup ki definition ke do hisse hain:

  1. "Jo use nahi karte, uski keemat nahi dete." Class mein virtual nahi → na vptr, na vtable, object ka size nahi badhta. Exceptions throw nahi hue → normal path pe (lagbhag) koi slowdown nahi.
  2. "Jo use karte ho, usse better haath se nahi likh sakte." std::vector ≈ haath se likha dynamic array. std::sort aksar C ke qsort se fast hota hai: qsort har comparison pe function pointer call karta hai, jabki std::sort template hai toh comparator inline ho jaata hai.

Java/Python mein kuch keemat hamesha deni padti hai (JVM, GC, runtime type checks), chahe feature use karo ya nahi.

Depth point

Ye principle har jagah 100% nahi hai. Exceptions aur RTTI (dynamic_cast, typeid) binary size badhate hain, isliye game/embedded wale kabhi-kabhi inhe compiler flags se band kar dete hain. Ye bolna dikhata hai ki tum blindly nahi maan rahe.

10. Paradigm, multi-paradigm, templates

Paradigm = code likhne aur sochne ka style. Ek hi problem (numbers ka sum) 4 styles mein:

// 1. PROCEDURAL: data + functions alag, step-by-step
int sum(int arr[], int n) {
    int s = 0;
    for (int i = 0; i < n; i++) s += arr[i];
    return s;
}

// 2. OBJECT-ORIENTED: data aur uske functions ek object mein
class Wallet {
    int total = 0;                     // data chhupa hua (encapsulation)
public:
    void add(int x) { total += x; }
    int get() const { return total; }
};

// 3. GENERIC (templates): ek code, kisi bhi type ke liye
template <typename T>
T sum(const std::vector<T>& v) {
    T s{};
    for (const T& x : v) s += x;
    return s;
}

// 4. FUNCTIONAL-ish: functions ko values ki tarah pass karo
int s = std::accumulate(v.begin(), v.end(), 0,
                        [](int a, int b) { return a + b; });   // lambda

Multi-paradigm = language ek style force nahi karti, problem ke hisaab se choose karo. Java har cheez class mein likhwata hai, C++ nahi.

Templates (first principle)

Problem: max function chahiye int, double, string sab ke liye. Har type ke liye same logic copy-paste karna padega. Template = compiler ke liye ek saancha:

template <typename T>
T myMax(T a, T b) { return a > b ? a : b; }

myMax(3, 5);        // compiler khud int version banata hai
myMax(2.5, 1.5);    // compiler khud double version banata hai
  • Code compile time pe har type ke liye alag generate hota hai → runtime pe zero cost (zero-overhead).
  • Isliye templates = static (compile-time) polymorphism (Set 2 Q18, Top30 Q28 se connect).
  • Poora STL templates pe bana hai: vector<int>, vector<string> same template se.

11. General-purpose ka matlab

General-purpose = kisi ek domain ke liye nahi, kuch bhi bana sakte ho: OS, game, browser, compiler, trading system, embedded firmware.

Domain-specific language (DSL) = ek specific kaam ke liye bani:

  • SQL → database query
  • HTML/CSS → web page structure/style
  • MATLAB → numerical computing, matrices (general programming bhi ho sakti hai, par strength maths/engineering hai)

Self-check

Pehle khud jawab socho, phir kholo.

1. Function declare kiya, kabhi define nahi kiya. Compile error ya linker error? Kyun?

Linker error (undefined reference). Compiler ko declaration se signature mil gaya, toh call compile ho gayi. Linker ko us function ka machine code kisi bhi .o ya library mein nahi mila.

2. Linux pe compile kiya a.out Windows pe kyun nahi chalega? Do reasons.

(1) Executable format alag hai: Linux = ELF, Windows = PE. (2) OS se baat karne ke system calls alag hain. (Aur CPU alag ho, jaise x86 vs ARM, toh instruction set bhi alag.)

3. std::sort C ke qsort se fast kyun ho sakta hai?

qsort har comparison pe function pointer ke through call karta hai, jo inline nahi ho sakta. std::sort template hai, toh comparator ka type compile time pe pata hai aur compiler use inline kar deta hai.

4. Templates ko "static polymorphism" kyun kehte hain?

Ek hi naam/code alag types ke saath alag kaam karta hai (polymorphism), aur kaunsa version chalega ye compile time pe decide hota hai, kyunki har type ka code compiler pehle hi generate kar deta hai. Runtime pe koi lookup (vtable) nahi.

5. C++ "purely OOP" kyun nahi hai? Do reasons.

main() aur global functions/variables class ke bahar hote hain, aur int, char jaise primitive types objects nahi hain. Tum poora program bina class ke procedural style mein bhi likh sakte ho.

6. javac kya banata hai, aur g++ se kaise alag hai? JDK/JRE/JVM ka relation?

javac bytecode (.class) banata hai jo JVM chalata hai; g++ machine code banata hai jo CPU directly chalata hai. JDK ⊃ JRE ⊃ JVM: JVM bytecode chalata hai, JRE = JVM + libraries, JDK = JRE + javac + tools.
