Part 1: Abstract Class

1.1 Abstract Class kya hai?

Simple Hinglish mein: imagine tum ek class Animal bana rahe ho. Har animal awaaz karta hai, par actual awaaz animal pe depend karti hai: Dog → Bark, Cat → Meow, Cow → Moo. Ab agar hum Animal ka object banana hi nahi chahte (kyunki wo sirf ek general concept hai), toh hum use abstract class bana sakte hain.

Class tab abstract hoti hai jab usme kam se kam ek pure virtual function ho.

class Animal {
public:
    virtual void sound() = 0;
};

Dhyan do: virtual void sound() = 0; ko Pure Virtual Function kehte hain. = 0 use pure virtual banata hai. Ab inherit karte hain:

class Animal {
public:
    virtual void sound() = 0;
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Bark";
    }
};

// Animal a;  // ERROR

Dog d;
d.sound();
Bark

Animal ka object kyun nahi bana sakte? Kyunki wo abstract hai aur uske pure virtual function ki implementation nahi hai jo class ko concrete banaye. Compiler ka error:

class Animal {
public:
    virtual void sound() = 0;
};

Animal a;     // ERROR
error: cannot declare variable 'a' to be of abstract type 'Animal'
Interview answer (English)

"An abstract class is a class that contains at least one pure virtual function. It cannot be instantiated directly and is generally used as a base class to define a common interface for derived classes."

Important interview points
  • Abstract class ka object nahi, par uska pointer / reference ban sakta hai. Yahi poori idea hai: Animal* p = new Dog; (polymorphism).
  • Abstract class by value function parameter ya return type nahi ho sakti (object banana padega). Reference/pointer lo.
  • Abstract class mein data members aur normal (non-virtual) functions bhi ho sakte hain.
class Animal {
public:
    virtual void sound() = 0;
};
void f(Animal a) { }          // by value: Animal ka object banana padega
error: cannot declare parameter 'a' to be of abstract type 'Animal'
class Animal {
public:
    virtual void sound() = 0;
    virtual ~Animal() = default;
};
class Dog : public Animal { public: void sound() override { cout << "Bark "; } };
class Cat : public Animal { public: void sound() override { cout << "Meow "; } };
void speak(Animal& a) { a.sound(); }                  // reference chalta hai

Dog d; Cat c;
speak(d); speak(c);                                  // ek hi code, alag behaviour

Animal* arr[] = { new Dog, new Cat };               // abstract type ke POINTERS ka array theek
for (Animal* p : arr) { p->sound(); delete p; }
Bark Meow Bark Meow

Part 2: Pure Virtual Function

1.2 Pure Virtual Function kya hai?

Normal virtual function derived class ko override karne deta hai. Pure virtual ek step aage jaata hai: wo derived class ko batata hai "agar concrete class banna hai toh apni implementation dena zaroori hai."

virtual void functionName() = 0;

Example: Shape mein area() aur perimeter() pure virtual. Circle ne sirf area() override kiya toh:

class Shape {
public:
    virtual void area() = 0;
    virtual void perimeter() = 0;
};

class Circle : public Shape {
public:
    void area() override { cout << "Area of circle"; }
    // perimeter() override nahi kiya
};

Circle c;     // ERROR: Circle abhi bhi abstract hai
error: cannot declare variable 'c' to be of abstract type 'Circle'

Agar derived class saare inherited pure virtual functions override nahi karti, toh wo bhi abstract hi rehti hai.

Important interview question: pure virtual function ki definition ho sakti hai?

Haan! Ye thoda tricky C++ concept hai. Function = 0 ke saath declare hota hai, par class ke bahar alag se definition de sakte ho. Ye perfectly valid hai:

class Base {
public:
    virtual void show() = 0;
};

void Base::show() {
    cout << "Base show\n";
}

class Derived : public Base {
public:
    void show() override {
        Base::show();
        cout << "Derived show\n";
    }
};

Derived d;
d.show();
Base show
Derived show

Par yaad rakho: definition dene se function non-pure nahi banta. Class abstract hi rehti hai. Derived class chahe toh Base::show() likh ke base ki implementation explicitly bula sakti hai (upar Derived::show() ne yahi kiya).

Interview answer (English)

"A pure virtual function is a virtual function declared with = 0. It makes the class abstract and requires concrete derived classes to provide an implementation. A pure virtual function can still have a separate definition in C++."

Important interview points
  • Pure virtual = virtual ... = 0;. Class abstract ban jaati hai.
  • Definition class ke bahar alag se hoti hai (void Base::show() { ... }), declaration ke saath = 0 ke saath nahi.
  • Definition hone ke baad bhi class abstract hai: us class ka object nahi ban sakta.
  • Derived ko ye definition automatically nahi milti: use Base::show() likh ke explicitly bulana padta hai.

Part 3: Abstract Class ka Constructor

1.3 Kya abstract class ka constructor ho sakta hai?

Haan! Bilkul. Ye bahut common interview question hai. Tumhe lag sakta hai ki jab object hi nahi ban sakta toh constructor ki kya zarurat? Par yaad rakho: abstract class ka constructor tab chalta hai jab uski derived class ka object banta hai.

class Animal {
public:
    Animal() {
        cout << "Animal constructor\n";
    }

    virtual void sound() = 0;
};

class Dog : public Animal {
public:
    Dog() {
        cout << "Dog constructor\n";
    }

    void sound() override {
        cout << "Bark\n";
    }
};

Dog d;
Animal constructor
Dog constructor

Samjho: 1) Dog ka object banaya. 2) Pehle Animal ka constructor chala. 3) Phir Dog ka. Kyun? Kyunki base class ki construction derived se pehle hoti hai.

Interview answer (English)

"Yes, an abstract class can have a constructor. Although we cannot instantiate an abstract class directly, its constructor is called when an object of a derived class is created. It is useful for initializing common base-class data members."

Important interview points
  • Constructor kaam: base class ke common data members initialize karna.
  • Order: base constructor → derived constructor. Destructor mein ulta: derived → base.
  • Constructor ko virtual nahi bana sakte (alag topic: Virtual constructor, Section A #3).

Part 4: Pure Virtual Destructor

1.4 Pure virtual destructor ko body kyun chahiye?

Ye shayad is topic ka sabse tricky sawaal hai. Pehle samjho: normally base class mein virtual destructor isliye banate hain taaki base-class pointer se derived object delete karne pe sahi cleanup ho:

class Base {
public:
    virtual ~Base() {
        cout << "Base destructor\n";
    }
};

class Derived : public Base {
public:
    ~Derived() {
        cout << "Derived destructor\n";
    }
};

Base* ptr = new Derived();

delete ptr;
Derived destructor
Base destructor

Ab destructor ko pure virtual bana ke dekho: virtual ~Base() = 0; aur uski definition alag se likho (Base::~Base() { ... }). Declaration = 0 ke saath, par definition bhi di. Full chalta hua example 1.6 mein hai. Ye zaroori kyun hai?

class Base {
public:
    virtual ~Base() = 0;
};

Base::~Base() {                 // definition alag se, class ke bahar
    cout << "Base destructor\n";
}

Jab derived class ka object destroy hota hai toh destruction chain mein base class destructor bhi chalta hai. Destructor pure virtual ho tab bhi use implementation chahiye, kyunki base destructor chalna hi hai. Pure virtual destructor class ko abstract banata hai, par uski definition phir bhi zaroori hai.

Common interview trap: sirf declare kiya, define nahi kiya toh linker error aata hai jab derived object banta aur marta hai:

Undefined symbols for architecture arm64:
  "Base::~Base()", referenced from:
      Derived::~Derived() in your .o file

Ye message macOS linker ka hai. Linux/GCC pe aisa dikhta hai: undefined reference to `Base::~Base()'. Dono ka matlab same: ~Base() ki definition nahi mili.

Interview answer (English)

"A pure virtual destructor is declared using virtual ~Base() = 0, making the class abstract. However, it must still have a definition because the base-class destructor is invoked whenever a derived-class object is destroyed."

Important interview points
  • Kyun use karte hain? Jab class ko abstract banana ho par koi aur pure virtual function na ho, tab destructor ko pure virtual bana dete hain.
  • Virtual destructor zaroori kyun: base pointer se delete karo toh derived destructor bhi chale, warna leak/UB (video #51).
  • Body class ke bahar alag se: Base::~Base() { }. Bina body ke → linker error.

Part 5: Abstract Class vs Interface

1.5 Kya C++ mein Interface keyword hota hai?

Nahi! Java ki tarah C++ mein alag interface keyword nahi hota. C++ mein interface aam taur pe ek abstract class se banate hain jisme: (1) pure virtual functions, aur (2) ek virtual destructor ho.

class Vehicle {
public:
    virtual void start() = 0;
    virtual void stop() = 0;

    virtual ~Vehicle() = default;
};

class Car : public Vehicle {
public:
    void start() override {
        cout << "Car started\n";
    }

    void stop() override {
        cout << "Car stopped\n";
    }
};

Vehicle* v = new Car();

v->start();
v->stop();

delete v;
Car started
Car stopped
Abstract ClassInterface (C++ convention)
Pure aur non-pure virtual functions dono ho sakteAam taur pe sirf pure virtual functions
Data members ho sakteAam taur pe instance data members nahi
Constructors ho sakteTechnically ho sakte, par aksar zaroorat nahi
Common implementations de sakti haiPrimarily ek contract define karti hai
Inheritance supportInheritance support

Important distinction: C++ mein interface koi alag language feature nahi, ek design convention hai jo abstract class se implement hoti hai. Interface jaisi class mein technically aur members bhi ho sakte hain, par usse pure virtual functions + virtual destructor tak rakhna usual convention hai.

Interview answer (English)

"C++ does not have a dedicated interface keyword. An interface is typically represented using an abstract class containing only pure virtual functions and a virtual destructor. An abstract class can also contain data members, constructors, and implemented member functions, whereas an interface primarily defines a contract that derived classes must follow."

Important interview points
  • Interface class mein virtual ~Vehicle() = default; (ya {} body) zaroor do: base pointer se delete safe rahe.
  • Ek class kai interfaces implement kar sakti hai (multiple inheritance). Interfaces mein data nahi hota, isliye multiple inheritance ka asli dard (duplicate data) nahi aata.
  • Abstract class: kuch common code + kuch must-implement. Interface: sirf contract.

1.7 Bonus: constructor ke andar pure virtual call

Interviewer ek step aur gehra ja sakta hai: "constructor mein virtual function call kiya toh?" Constructor ke dauran object abhi sirf base type ka hota hai, derived hissa abhi bana nahi, isliye virtual call derived tak nahi pahunchta. Agar wo function pure virtual hai aur base mein uski koi implementation nahi, toh runtime pe program abort ho jaata hai:

class Base {
public:
    Base() { init(); }            // constructor ke andar virtual call
    void init() { f(); }          // f() pure virtual hai
    virtual void f() = 0;
    virtual ~Base() = default;
};
class Derived : public Base { public: void f() override { cout << "Derived f\n"; } };

Derived d;
pure virtual method called
terminate called without an active exception
[exit code -6]

(Derived::f() kabhi nahi chala: "pure virtual method called".) Agar constructor mein seedha f() likho toh compiler warning deta hai ("pure virtual called from constructor") aur program link hi nahi hota (undefined symbol, maine check kiya). Upar jaisa indirect call link ho jaata hai par run-time pe crash karta hai. Ye topic gehra Section A #2 (vtable/vptr) aur #3 (virtual constructor) mein aayega.

Self-check

1. Abstract class kab banti hai, aur uska object kyun nahi ban sakta?
Jab kam se kam ek pure virtual function (= 0) ho. Uski implementation nahi hoti, isliye object adhoora hoga. Pointer/reference ban sakte hain.
2. Pure virtual function ki body ho sakti hai?
Haan, class ke bahar alag se. Par class abstract hi rehti hai, aur derived ko Base::f() se explicitly bulana padta hai.
3. Abstract class ka constructor kyun, jab object hi nahi bana sakte?
Derived object banne pe base constructor chalta hai (base pehle). Common members initialize karne ke kaam aata hai.
4. Pure virtual destructor ki body kyun zaroori?
Derived object marne pe base destructor chalta hi hai. Body nahi hui toh linker error.
5. C++ mein interface kaise banate hain?
Interface keyword nahi. Abstract class jisme sirf pure virtual functions aur virtual destructor ho.
6. Derived class ne ek pure virtual function override nahi kiya toh?
Derived bhi abstract rahegi; uska object banane pe compile error.

Part 2: Default constructor

5.2 Default constructor

Bina argument pass kiye object banata hai.

class Test {
public:
    Test() {
        cout << "Default Constructor";
    }
};

Test t;
Default Constructor

Agar tumne koi bhi constructor khud declare nahi kiya, toh compiler implicitly default constructor declare kar deta hai. Par:

class Test {
public:
    Test(int x) {}
};

Test t;    // ERROR
error: no matching function for call to 'Test::Test()'

Humne parameterized constructor declare kiya, isliye compiler ne implicit default constructor nahi banaya. Wapas chahiye toh Test() = default; likho (5.9).

Interview answer (English)

"The compiler implicitly declares a default constructor only if we haven't declared any constructor ourselves. As soon as we declare a parameterized constructor, the implicit default constructor is no longer generated."

Part 3: Copy constructor

5.3 Copy constructor

Maujooda object se naya object banata hai. Syntax: ClassName(const ClassName& obj);

class Test {
public:
    int x;

    Test(int a) {
        x = a;
    }

    Test(const Test& obj) {
        x = obj.x;
        cout << "Copy Constructor ";
    }
};

Test t1(10);
Test t2 = t1;
Copy Constructor

Dhyan do: Test t2 = t1; copy constructor call karta hai, kyunki t2 ban raha hai (ye assignment nahi, initialization hai).

Important distinction: Copy constructor vs Copy assignment
  • Test b = a; → naya object banta hai → Copy constructor.
  • b = a; (b pehle se hai) → maujooda object update hota hai → Copy assignment.
class Test {
public:
    int x;
    Test(int a) : x(a) {}
    Test(const Test& o) : x(o.x) { cout << "Copy Constructor\n"; }
    Test& operator=(const Test& o) { cout << "Copy Assignment\n"; x = o.x; return *this; }
};

Test t1(10);
Test t2 = t1;      // naya object ban raha hai: Copy constructor
Test t3(t1);       // ye bhi naya object: Copy constructor

Test t4(20);
t4 = t1;           // t4 pehle se maujood: Copy assignment
Copy Constructor
Copy Constructor
Copy Assignment

Pehle do Copy Constructor (t2 = t1 wali line aur t3(t1)), teesra Copy Assignment (t4 = t1). Compiler dono copy operations implicitly generate kar sakta hai (rules 5.6 mein).

Interview trap: copy constructor ka parameter by value kyun nahi?

Copy constructor const Test& leta hai, Test by value nahi. By value lete toh argument ko copy karne ke liye copy constructor chahiye, uske liye phir copy constructor... infinite recursion. Isliye compiler seedha mana kar deta hai:

error: invalid constructor; you probably meant 'Test (const Test&)'
Interview answer (English)

"A copy constructor creates a new object from an existing object. It takes a const reference to the same class. Taking it by value would need a copy to make the copy, causing infinite recursion. For `Test b = a;` the copy constructor runs, while `b = a;` on an existing object runs the copy assignment operator."

Part 4: Copy assignment operator

5.4 Copy assignment operator

Ek existing object ka data doosre existing object mein copy karta hai. Syntax: ClassName& operator=(const ClassName& obj);

class Test {
public:
    int x;

    Test(int a) : x(a) {}

    Test& operator=(const Test& obj) {
        cout << "Copy Assignment ";
        x = obj.x;
        return *this;
    }
};

Test t1(10);
Test t2(20);

t2 = t1;
Copy Assignment

Return type Test& kyun?

  • Chained assignment chalta hai: a = b = c.
  • *this return karke current object hi wapas milta hai.
class Test {
public:
    int x;
    Test(int a) : x(a) {}
    Test& operator=(const Test& obj) {
        x = obj.x;
        return *this;
    }
};

Test a(1), b(2), c(3);
a = b = c;                           // b = c pehle, phir a = (b = c)
cout << a.x << b.x << c.x << "\n";
333

Agar operator= void return kare toh a = b = c compile hi nahi hota (b = c ka result void hai, aage assign kaise ho):

error: no match for 'operator=' (operand types are 'Test' and 'void')
Yaad rakho
  • Resource wale class mein assignment mein pehle purana resource delete, phir naya lo (5.7 mein poora code) aur if (this != &o) self-assignment check lagao, warna a = a pe apna hi data delete ho jaayega.

Part 5: Move constructor and move assignment

5.5 Move semantics

Socho ek object ke paas dynamically allocated array hai. Copy mein hum alag resource banate hain (duplicate). Move mein hum maujooda resource ki ownership transfer kar dete hain, naya banate hi nahi.

Ek line mein

Copy = duplicate the resource. Move = transfer ownership of the resource.

Move constructor: doosre object se resources leke naya object banata hai. Syntax: ClassName(ClassName&& obj); Ye && rvalue reference hai.

class Test {
public:
    int* ptr;

    Test(int x) {
        ptr = new int(x);
    }

    Test(Test&& obj) {
        ptr = obj.ptr;
        obj.ptr = nullptr;

        cout << "Move Constructor\n";
    }

    ~Test() {
        delete ptr;
    }
};

Test t1(10);
Test t2(std::move(t1));

cout << (t1.ptr == nullptr) << " " << *t2.ptr << "\n";   // t1 khali, t2 ke paas 10
Move Constructor
1 10

Kya hua?

Move se pehle:    t1 → [ memory jisme 10 hai ]

std::move(t1) + move constructor ke baad:
                  t1 → nullptr
                  t2 → [ wahi memory jisme 10 hai ]

Humne pointer transfer kiya, naya memory allocate karke value copy nahi ki. obj.ptr = nullptr zaroori hai: warna t1 aur t2 dono ka destructor same memory delete karte (double delete).

Important: std::move() khud kuch move nahi karta

Wo sirf expression ko rvalue reference mein cast karta hai, taaki move operations select ho sakein. Asli move move-constructor/assignment ke andar hota hai:

string s = "hello";
string&& r = std::move(s);       // sirf cast hua, koi move nahi
cout << "[" << s << "]\n";       // s abhi bhi "hello"

string t = std::move(s);         // asli move yahan hua (string ka move constructor)
cout << "[" << s << "] [" << t << "]\n";
[hello]
[] [hello]

Pehli line mein std::move(s) ke baad bhi s abhi "hello" hai. Asli move string t = std::move(s); mein hua. (Moved-from object "valid but unspecified" state mein hota hai; GCC ka string khaali ho jaata hai, par is par bharosa mat karo.)

Move assignment operator: jab destination object pehle se maujood ho.

class Test {
public:
    int* ptr;
    Test(int x) : ptr(new int(x)) {}
    Test(Test&& obj) : ptr(obj.ptr) { obj.ptr = nullptr; }

    Test& operator=(Test&& obj) {
        cout << "Move Assignment\n";
        if (this != &obj) {
            delete ptr;

            ptr = obj.ptr;
            obj.ptr = nullptr;
        }
        return *this;
    }

    ~Test() { delete ptr; }
};

Test a(10), b(20);
b = std::move(a);
cout << (a.ptr == nullptr) << " " << *b.ptr << "\n";
Move Assignment
1 10

Teen steps: (1) destination ka purana resource release karo, (2) source ka resource transfer karo, (3) source ko valid state mein chhodo (nullptr). this != &obj check self-move se bachata hai.

Interview answer (English)

"Move semantics let us transfer ownership of a resource from one object to another instead of duplicating it. The move constructor takes an rvalue reference, steals the source's pointer and leaves the source in a valid but empty state, for example by setting it to nullptr. std::move itself doesn't move anything; it only casts its argument to an rvalue reference so that the move operations get selected."

Copy assignmentGenerally implicit agar user-declared nahi; delete bhi ho sakta hai
Move constructorKoi user-declared copy ctor, copy assignment, move assignment ya destructor nahi
Move assignmentKoi user-declared copy ctor, copy assignment, move ctor ya destructor nahi

Important nuances:

  • User-declared move ctor ya move assignment hone pe implicitly declared copy operations deleted ho jaate hain.
  • Tumne copy ctor, copy assignment ya destructor declare kiya toh compiler move operations implicitly declare nahi karta.
  • Agar koi member ya base class copy nahi ho sakti, toh implicit copy operations bhi deleted ho jaate hain.
  • User-declared destructor wali class mein implicit copy operations deprecated hain, resource management ke liye un par depend mat karo.

Interview takeaway: copy / destructor operations khud declare karna automatic move generation ko affect karta hai. Neeche teeno nuances ka proof (GCC output):

(a) Destructor declare kiya → move generate nahi, copy chalta hai. A mein kuch declare nahi, B mein sirf ~B() {}:

struct Noisy {
    Noisy() {}
    Noisy(const Noisy&)          { cout << "  Noisy copy\n"; }
    Noisy(Noisy&&) noexcept      { cout << "  Noisy move\n"; }
};

struct A { Noisy n; };                    // koi special function declare nahi kiya
struct B { Noisy n; ~B() {} };            // sirf destructor declare kiya

cout << "A:\n"; A a1; A a2 = std::move(a1);
cout << "B:\n"; B b1; B b2 = std::move(b1);
A:
  Noisy move
B:
  Noisy copy

A ka implicit move constructor member ko move karta hai. B mein destructor likha, isliye move constructor aaya hi nahi aur std::move(b1) ne chupchaap copy kar diya. Koi error nahi, bas performance gayi. Yahi sabse common silent bug hai.

(b) Sirf copy ctor declare kiya → std::move bhi copy ho jaata hai:

struct W {
    W() {}
    W(const W&) { cout << "W copy constructor\n"; }     // sirf copy declare kiya
};

W w1;
W w2 = std::move(w1);       // move maanga, copy mila: const W& rvalue ko bhi bind ho jaata hai
W copy constructor

Move constructor nahi hai, toh rvalue const W& se bind hokar copy constructor chalata hai.

(c) Move constructor declare kiya → copy deleted:

struct M {
    M() = default;
    M(M&&) = default;            // move constructor declare kiya
};

M a;
M b = a;                         // copy: ERROR
error: use of deleted function 'constexpr M::M(const M&)'

(d) Member copy nahi ho sakta → class ka implicit copy bhi delete: (unique_ptr member)

struct H {
    unique_ptr<int> p;           // unique_ptr copy nahi hota
};

H a;
H b = a;                         // H ka implicit copy ctor delete ho gaya
error: use of deleted function 'H::H(const H&)'
Interview answer (English)

"The compiler generates the default constructor only if we declare no constructors. Move operations are implicitly declared only if we haven't declared a copy constructor, copy assignment, move assignment or destructor. If we declare a move operation, the copy operations are defined as deleted. And if we declare a destructor or a copy operation ourselves, std::move silently falls back to copying."

Part 7: Rule of 3

5.7 Rule of 3

Agar tumhari class koi resource manually manage karti hai (jaise dynamic memory), toh in teeno ko saath mein implement karne ka socho:

  1. Destructor
  2. Copy constructor
  3. Copy assignment operator

Kyun? Maan lo class mein sirf constructor (new) aur destructor (delete) hai. Compiler ka copy constructor shallow copy karta hai, yaani sirf pointer copy:

class Test {
public:
    int* ptr;
    Test(int x) { ptr = new int(x); }
    // destructor / copy constructor nahi likha: compiler ka copy constructor chalega
};

Test t1(10);
Test t2 = t1;

cout << (t1.ptr == t2.ptr) << "\n";     // 1 = dono ka address same
*t2.ptr = 99;
cout << *t1.ptr << "\n";                // t2 badla, t1 bhi badal gaya
1
99

t1.ptr == t2.ptr (dono ek hi memory block ko point karte hain), isliye t2 badalne se t1 bhi badal gaya. (Is demo mein destructor nahi hai, warna agla step.)

Ab destructor wapas lagao. Dono objects marte waqt same memory do baar delete karte hain: double deletion = undefined behavior:

class Test {
public:
    int* ptr;
    Test(int x) { ptr = new int(x); }
    ~Test() { delete ptr; }
};

Test t1(10);
Test t2 = t1;       // shallow copy
[abort, exit code 134: macOS prints no message here]

Ye abort hua (macOS pe is run mein koi message nahi chhapa). Linux (glibc) pe aam taur pe free(): double free detected in tcache 2 jaisa message aata hai, par wo maine yahan run nahi kiya. AddressSanitizer (-fsanitize=address) se maine verify kiya, wo seedha batata hai:

ERROR: AddressSanitizer: attempting double-free on 0x602000000150 in thread T0

Fix = Rule of 3, deep copy:

class Test {
    int* ptr;
public:
    Test(int x) { ptr = new int(x); cout << "ctor\n"; }

    Test(const Test& o) {                       // deep copy
        ptr = new int(*o.ptr);
        cout << "copy ctor\n";
    }

    Test& operator=(const Test& o) {
        if (this != &o) {
            delete ptr;                         // purana resource chhodo
            ptr = new int(*o.ptr);              // naya alag resource lo
        }
        cout << "copy assign\n";
        return *this;
    }

    ~Test() { cout << "dtor\n"; delete ptr; }

    int get() const { return *ptr; }
    void set(int v) { *ptr = v; }
    const int* addr() const { return ptr; }
};

Test t1(10);
Test t2 = t1;
t2.set(99);
cout << t1.get() << " " << t2.get() << " same address? " << (t1.addr() == t2.addr()) << "\n";

Test t3(5);
t3 = t1;

copy ctor

dtor

Dekho: t1 10 hi raha, t2 99 hua, addresses alag (0 = same nahi). Teen destructors, har object ka apna resource.

Interview answer (English)

"The Rule of Three says that if a class needs a user-defined destructor, copy constructor or copy assignment operator, it almost certainly needs all three. The reason is that the compiler-generated copy does a shallow copy, so two objects end up owning the same pointer, and when both destructors run the memory is deleted twice, which is undefined behavior."

Part 8: Rule of 5

5.8 Rule of 5

C++11 ne move semantics diya. Ab resource manually manage karte ho toh paanchon ka socho:

  1. Destructor
  2. Copy constructor
  3. Copy assignment
  4. Move constructor
  5. Move assignment

Kyun? Copy operations duplication sambhalte hain, move operations resource transfer, destructor cleanup. Isse copy aur move dono par control milta hai. Poora example, har operation print karta hai:

class Buf {
    int* p;
public:
    Buf(int x) : p(new int(x)) { cout << "ctor " << x << "\n"; }
    Buf(const Buf& o) : p(new int(*o.p)) { cout << "copy ctor\n"; }
    Buf(Buf&& o) noexcept : p(o.p) { o.p = nullptr; cout << "move ctor\n"; }

    Buf& operator=(const Buf& o) {
        if (this != &o) { delete p; p = new int(*o.p); }
        cout << "copy assign\n";
        return *this;
    }
    Buf& operator=(Buf&& o) noexcept {
        if (this != &o) { delete p; p = o.p; o.p = nullptr; }
        cout << "move assign\n";
        return *this;
    }
    ~Buf() { delete p; cout << "dtor\n"; }
};

Buf a(1);
Buf b = a;                  // copy ctor      (a lvalue hai)
Buf c = std::move(a);       // move ctor      (a ko rvalue bana diya)
Buf d(4);
d = b;                      // copy assign
d = std::move(c);           // move assign
ctor 1
copy ctor
move ctor
ctor 4
copy assign
move assign
dtor
dtor
dtor
dtor

Padho: b = a (a lvalue) → copy ctor; std::move(a) → move ctor; d = b → copy assign; d = std::move(c) → move assign. Aakhir mein 4 destructors (a, b, c, d).

Interview answer (English)

"The Rule of Five extends the Rule of Three for C++11. If a class manages a resource manually, we should consider defining the destructor, copy constructor, copy assignment, move constructor and move assignment together. Copy duplicates the resource, move transfers it, and the destructor cleans up."

Part 9: = default and = delete

5.9 = default aur = delete

Interview mein bahut poochhe jaate hain.

= default compiler ko bolta hai: "iska default implementation tum generate karo." Tab kaam aata hai jab tumne doosra constructor declare kiya par default constructor bhi chahiye:

class Test {
public:
    int v = 7;
    Test() = default;                 // compiler wala default constructor wapas maanga
    Test(int x) : v(x) {}
};

Test a;          // Test() = default ki wajah se chalta hai
Test b(5);
cout << a.v << " " << b.v << "\n";
7 5

= delete function ko explicitly disable karta hai:

class Test {
public:
    Test() = default;
    Test(const Test&) = delete;
};

Test t1;
Test t2 = t1;       // ERROR
error: use of deleted function 'Test::Test(const Test&)'

Copying mana hai. Common use cases:

  • Copying rokna (copy constructor delete). unique_ptr, std::thread, mutex isi tarah non-copyable hain.
  • Assignment rokna (copy assignment delete):
class Test {
public:
    Test() = default;
    Test(const Test&) = delete;
    Test& operator=(const Test&) = delete;
};

Test t1, t2;
t2 = t1;            // ERROR
error: use of deleted function 'Test& Test::operator=(const Test&)'
  • Unwanted implicit conversion / function call rokna: koi bhi function delete kar sakte ho:
void show(int x) { cout << x << "\n"; }
void show(double) = delete;           // double se call mana hai

show(5);                              // theek
show(3.5);                            // ERROR
error: use of deleted function 'void show(double)'
Interview answer (English)

"= default asks the compiler to generate the default implementation of a special member function, for example to get the default constructor back after declaring another constructor. = delete explicitly disables a function; it is used to make a class non-copyable or to prevent unwanted calls and implicit conversions, and the error is reported at compile time."

"Ideally we follow the Rule of Zero: let members like std::string, std::vector or std::unique_ptr manage resources so that the compiler-generated special functions are correct. Only when a class directly owns a raw resource do we implement the Rule of Three or Five."

Self-check

1. Copy constructor aur copy assignment mein fark?
Copy constructor naya object banata hai (Test b = a;), copy assignment maujooda object update karta hai (b = a;).
2. Copy constructor ka parameter const reference kyun?
By value hota toh argument copy karne ke liye copy constructor chahiye, infinite recursion. Compile error: invalid constructor. const isliye ki source badle nahi aur rvalue/temporary bhi bind ho.
3. operator= Test& kyun return karta hai?
Chained assignment (a = b = c) ke liye; *this return hota hai.
4. Rule of 3 aur Rule of 5?
Rule of 3: destructor + copy ctor + copy assignment. Rule of 5: inme move ctor + move assignment. Raw resource manage karte ho toh saath mein define karo.
5. std::move kya karta hai?
Sirf rvalue reference mein cast. Move khud move constructor/assignment karta hai. std::move(x); akele likhne se kuch nahi hota.
6. Class mein destructor likha, ab std::move(obj) se kya hoga?
Move constructor generate hi nahi hua, isliye copy constructor chalta hai (agar copy available hai). Koi error nahi, bas move ka fayda gaya.
7. Default constructor kab nahi milta?
Jab tumne koi bhi constructor khud declare kiya. Test() = default; se wapas maang sakte ho.
8. = delete kab use karte ho?
Copy/assignment rokne ke liye (non-copyable class), ya kisi function ka koi overload/conversion rokne ke liye (void f(double) = delete;).
9. Shallow copy mein kya problem hai?
Do objects ek hi pointer rakhte hain: ek badle toh doosra badle, aur dono destructors same memory delete karte hain (double free, undefined behavior). Fix: deep copy (Rule of 3) ya move/smart pointer.

Part 1: const kya hai?

6.1 What does const mean?

const ka matlab: is declaration ke through cheez modify nahi ho sakti.

const int x = 10;

x = 20;        // ERROR
error: assignment of read-only variable 'x'

Initialize hone ke baad x badal nahi sakte. Ye bhi same hai:

int const x = 10;

const int x aur int const x equivalent hain (const type ke pehle ya baad, same).

Dhyan do: "through that declaration"

Const ka matlab ye nahi ki memory kabhi badal hi nahi sakti. const int* p = &a; mein *p se a nahi badal sakte, par a khud (agar const nahi hai) seedha badal sakta hai. Ye 6.4 mein dikhega.

Part 2: Const member functions

6.2 Const member functions

Const member function ye promise karta hai ki wo object ke ordinary (non-mutable) data members modify nahi karega. Syntax: const function ke parentheses ke baad:

class Student {
public:
    int marks;

    void display() const {
        cout << marks;
    }
};
Ye same nahi hai: void display() const; vs const void display();

Pehle mein const function ka hai (this ko const banata hai). Doosre mein const sirf return type ka hai, function const nahi bana. Proof: const object pe call karo:

class A {
public:
    const void show() { cout << "hi"; }     // const IS BAAR return type ka hai, function ka nahi
};

const A a;
a.show();                                   // ERROR: function const nahi bana
error: passing 'const A' as 'this' argument discards qualifiers [-fpermissive]

Const function ke andar member badalne ki koshish:

class Student {
public:
    int marks = 90;

    void update() const {
        marks = 100;       // ERROR
    }
};

Student s;
error: assignment of member 'Student::marks' in read-only object

Const member function ordinary data members modify nahi kar sakta.

Important: Const objects

class Student {
public:
    void display() const {
        cout << "Display";
    }

    void update() {
        cout << "Update";
    }
};

const Student s;

s.display();    // Valid
s.update();     // ERROR
error: passing 'const Student' as 'this' argument discards qualifiers [-fpermissive]

Rule:

  • Const object → const member functions bula sakta hai.
  • Const object → non-const member functions nahi bula sakta.

Kyun? Kyunki non-const member function object ko modify kar sakta hai, aur const object ko modify nahi hona chahiye. (Error message mein "discards qualifiers": this ka const hat raha tha.) Non-const object dono bula sakta hai:

class Student {
public:
    void display() const { cout << "Display\n"; }
    void update()        { cout << "Update\n"; }
};

const Student s1;
s1.display();           // const object + const function: theek

Student s2;             // non-const object dono bula sakta hai
s2.display();
s2.update();

Update
Interview answer (English)

"A const member function promises not to modify the object's ordinary data members. Internally it makes the `this` pointer a pointer to const. A const object can only call const member functions, because a non-const member function would be allowed to modify the object."

Part 3: mutable

6.3 What is mutable?

mutable ek data member ko const member function ke andar bhi modify karne deta hai.

class Test {
public:
    int x = 10;
    mutable int count = 0;

    void display() const {
        count++;
        cout << x << " " << count;
    }
};

const Test t;
t.display();
10 1
  • x ko display() ke andar badal nahi sakte.
  • count badal sakte hain kyunki wo mutable hai.

Mutable ki zaroorat kyun? Common use cases:

  • Calculated values cache karna.
  • Logging ya access counters rakhna.
  • Internal bookkeeping jo object ki logical state nahi badalti.

Caching ka example, ek baar calculate, doosri baar seedha cache:

class Circle {
    double r;
    mutable bool cached = false;        // cache: logically const operation ke andar badalta hai
    mutable double area_cache = 0;
public:
    Circle(double r) : r(r) {}
    double area() const {
        if (!cached) {
            cout << "(calculating) ";
            area_cache = 3.14 * r * r;
            cached = true;
        }
        return area_cache;
    }
};

const Circle c(2);
cout << c.area() << "\n";
cout << c.area() << "\n";               // is baar calculation nahi
(calculating) 12.56
12.56

area() const hai (logically kuch nahi badla), par andar cache fields mutable hain isliye update ho sake. (Lambda wala mutable alag cheez hai, wo Lambda 3.2 mein hai.)

Interview definition

mutable allows a non-static data member to be modified even inside a const member function or through a const object.

Part 4: Const pointers

6.4 Const pointers: extremely important!

Yahan bahut log confuse hote hain. Teen major declarations hain. Har ek ke saath compiler ka asli error bhi dekho (Valid wali line compile hoti hai, error sirf ERROR wali line pe aata hai).

A. const int* ptr: pointer to a constant integer. Pointer kahin aur point kara sakte ho, par us pointer se value modify nahi kar sakte.

int a = 10;
int b = 20;

const int* ptr = &a;

ptr = &b;       // Valid
*ptr = 30;      // ERROR
error: assignment of read-only location '* ptr'

Data const hai, pointer nahi.

B. int* const ptr: constant pointer to an integer. Pointer ko kahin aur point nahi karwa sakte, par value modify kar sakte ho.

int a = 10;
int b = 20;

int* const ptr = &a;

*ptr = 30;      // Valid
ptr = &b;       // ERROR
error: assignment of read-only variable 'ptr'

Pointer const hai, data nahi.

C. const int* const ptr: constant pointer to a constant integer. Dono nahi badal sakte.

int a = 10;
int b = 20;

const int* const ptr = &a;

*ptr = 30;      // ERROR
ptr = &b;       // ERROR
error: assignment of read-only location '*(const int*)ptr'
error: assignment of read-only variable 'ptr'

Pointer aur data, dono const. (Valid operations ka output: 6.8.)

6.5 Quick comparison table

DeclarationModify *ptr?Reassign ptr?
const int* ptrNoYes
int* const ptrYesNo
const int* const ptrNoNo
Easy trick: variable ke naam se bahar ki taraf padho
  • const int* ptr; → pointer to const int.
  • int* const ptr; → const pointer to int.
  • const int* const ptr; → const pointer to const int.

Shortcut: * ke baayein wala const → data const. * ke daayein wala const → pointer const. (int const* p aur const int* p same hain, kyunki dono mein const * ke baayein hai.)

Interview answer (English)

"In `const int* p` the pointee is const, so we can re-point the pointer but not modify the value through it. In `int* const p` the pointer itself is const, so we can modify the value but cannot re-point it. In `const int* const p` both are const. A quick way to read it: look at which side of the star the const sits on. Left of the star makes the data const, right of the star makes the pointer const."

Part 5: Const reference

6.6 Bonus: const reference

Ye bhi bahut milega:

void display(const int& x) {
    cout << x;
}

Iska matlab:

  • Argument pass karte waqt copy nahi banti.
  • Function is reference ke through x ko modify nahi kar sakta.

Bade objects (string, vector, class) pass karne ke liye bahut kaam ka. Modify karne ki koshish:

void display(const int& x) {
    cout << x;
    x = 5;                // ERROR: const reference se badal nahi sakte
}

int n = 1;
display(n);
error: assignment of read-only reference 'x'

Ek aur fayda: const reference temporary (rvalue) ko bhi bind kar leta hai, non-const reference nahi:

void byConst(const int& x) { cout << x << "\n"; }
void byRef(int& x)         { cout << x << "\n"; }

byConst(5);               // theek: const& temporary (5) ko bind kar leta hai
byRef(5);                 // ERROR
error: cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int'
Interview answer (English)

"Passing by const reference avoids copying the argument and prevents the function from modifying it. It is the standard way to pass large objects that the function only needs to read. A const reference can also bind to temporaries, which a non-const reference cannot."

    const int& get() const { cout << "const get       "; return v; }
};

Box b1;
const Box b2;
b1.get() = 50;            // non-const object: non-const version, v badal sakte hain
cout << "\n";
cout << b1.get() << "\n";
cout << b2.get() << "\n"; // const object: const version (v nahi badal sakte)
non-const get  
non-const get  50
const get       7

5. Const data member ya reference member ko constructor ke body mein assign nahi kar sakte, initializer list mein hi initialize hota hai:

class Test {
    const int id;
public:
    Test(int i) {
        id = i;              // ERROR: yahan tak toh id ban chuka hai, ab assignment ho rahi hai
    }
};

Test t(1);
error: uninitialized const member in 'const int' [-fpermissive]
error: assignment of read-only member 'Test::id'

Sahi tareeka (initializer list):

class Test {
    const int id;
    const int& ref;
public:
    Test(int i, int& r) : id(i), ref(r) {}       // const / reference member initializer list mein hi
    void show() const { cout << id << " " << ref << "\n"; }
};

int n = 5;
Test t(1, n);
t.show();
1 5

6. const_cast: const hatata hai. Agar object asli mein const nahi tha toh theek:

int a = 10;                       // asli mein const NAHI hai
const int* p = &a;
int* q = const_cast<int*>(p);     // const hata diya
*q = 20;                          // theek: a asli mein const nahi tha
cout << a << "\n";
20
Dhyan: asli const object ko const_cast se badalna undefined behavior hai

Agar const int a = 10; (asli const) ho aur const_cast se *q = 20 karo, toh undefined behavior hai (maine ise run nahi kiya, UB ka output bharosemand nahi). const_cast sirf tab theek jab pointee asli mein const nahi tha, aur interview mein ise "last resort / purane API ke liye" hi bolo.

7. Note: const Test t; (bina initializer) tabhi chalta hai jab class ke members ka default initializer ho (jaise int x = 10;) ya koi user-provided constructor ho. Upar mutable example isiliye compile hua.

Self-check

1. void f() const ka matlab kya hai?
Function object ke ordinary data members modify nahi karega (this pointer-to-const ban jaata hai). Const object ye function bula sakta hai.
2. void f() const; aur const void f(); mein fark?
Pehle mein function const hai. Doosre mein sirf return type const void hai, function const nahi (const object pe call error deta hai).
3. Const object non-const function kyun nahi bula sakta?
Non-const function object ko modify kar sakta hai, jo const object ke saath allowed nahi. Error: passing 'const X' as 'this' argument discards qualifiers.
4. mutable kya hai aur kab use karte hain?
Non-static data member jo const function/const object ke andar bhi badal sakta hai. Caching, counters, logging, internal bookkeeping jo logical state nahi badalte.
5. const int* p, int* const p, const int* const p mein fark?
Pehla: value nahi badal sakte, pointer badal sakte. Doosra: value badal sakte, pointer nahi. Teesra: dono nahi.
6. const int& parameter kyun use karte hain?
Copy nahi banti aur function value badal nahi sakta. Temporary (rvalue) ko bhi bind kar leta hai.
7. Const data member ko kaise initialize karte hain?
Constructor ke initializer list mein. Body mein assignment error hai.
8. int* ko const int* mein de sakte hain? Ulta?
int* → const int* theek. const int* → int* error (invalid conversion), const_cast chahiye.
