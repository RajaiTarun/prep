Compilation & linking

#2

Explain the compilation process of a C++ program.

"A C++ program goes through four stages: the preprocessor handles directives like #include and macros, the compiler translates the code into assembly, and the assembler turns that into an object file. The linker then combines all the object files and libraries into an executable. Finally, the loader, which is part of the operating system, loads the executable into memory and runs it."

g++ -save-temps main.cpp
# main.ii (preprocessed) → main.s (assembly) → main.o (object) → a.out

#37

How does C++ support function overloading?

"C++ achieves function overloading through name mangling. The compiler encodes the parameter types into each function's name, so print(int) becomes _Z5printi and print(double) becomes _Z5printd, giving the linker two distinct symbols. C does not mangle names, which is why C has no overloading. And main is never mangled, because it is the program's entry point."

print(int)    → _Z5printi
print(double) → _Z5printd

#36

When and why do we use extern "C"?

"We use extern "C" when calling a C library from C++ code. C++ mangles function names but C does not, so the linker looks for the mangled name, cannot find it, and reports an undefined reference. extern "C" tells the compiler not to mangle those names, so they match the names in the C library and linking succeeds."

extern "C" {
    void fun(void);   // name not mangled
}

#57

Why must a static data member be defined in the .cpp file, not the header?

"A static data member written inside the class is only a declaration; it needs exactly one definition, like int Animal::count = 0;, outside the class. If I put that definition in the header, every source file that includes the header gets its own copy, because #include just pastes the text. Each source file compiles fine on its own, but when the linker combines the object files it finds multiple definitions of the same variable and fails with a 'multiple definition' error. Include guards do not help, because they only prevent double inclusion within a single source file. So the rule is: declare the static member in the header and define it in exactly one .cpp file. Since C++17, an inline static member can also be defined directly in the header."

// animal.h
class Animal { static int count; };   // declaration only
// animal.cpp (exactly one)
int Animal::count = 0;                 // definition
// in header -> every .cpp gets a copy -> linker: multiple definition

Memory layout

#1

What is structure padding?

"Structure padding means the compiler inserts extra bytes between members so that each member sits at an address that is a multiple of its own size. This lets the processor read each value in a single memory access, since a 32-bit CPU reads 4 bytes, one word, at a time. That is why a struct of char, char, int, char takes 12 bytes instead of 7. We can reduce padding by ordering members by size, or disable it with #pragma pack(1), at the cost of slower access."

struct S { char a; char b; int i; char c; };
sizeof(S);   // 12, not 7

#77

How does padding work when a struct contains another struct?

"When a struct contains another struct, the alignment is decided by the largest member inside the nested struct, not by the nested struct's total size. For example, struct A { int; double; } is 16 bytes, but inside another struct it is aligned to an 8-byte boundary because of the double. So int, int, A takes 24 bytes while int, A, int takes 32 bytes, even though the members are the same. Member order matters."

struct A { int x; double d; };        // 16
struct B { int x; int y; A a; };      // 24
struct C { int x; A a; int y; };      // 32

#10

What is big endian vs little endian?

"Endianness is the order in which the bytes of a multi-byte value are stored in memory. Big endian stores the most significant byte at the lowest address, while little endian stores the least significant byte first. Only the byte order differs; the bits inside each byte stay the same. Neither is better, but it matters when machines with different endianness exchange data over a network. To check a system, store int i = 1 and read its first byte through a char*: if it is 1, the system is little endian."

0x01234567  →  big: 01 23 45 67   little: 67 45 23 01
unsigned int i = 1;  char* c = (char*)&i;
if (*c) → little endian

Dynamic memory & pointers

#3

How does delete[] know how many objects to destroy?

"delete[] needs the array size n so it can call the destructor n times. Compilers store n in one of two ways. With over-allocation, they allocate one extra word, store n at the start, and return a pointer just past it; delete[] steps back one word to read n. With an associative array, they keep a separate table that maps the pointer to n and look it up during deletion. In both cases the destructors run in reverse order, and then the memory is freed."

[ n | obj0 | obj1 | ... ]
      ↑ p   (n is stored one word before p)

malloc vs calloc: which is faster, and when to use which?

"malloc returns memory as it is, while calloc initializes it to zero first, which is why calloc is slightly slower. However, if you need zero-initialized memory, calloc is better than malloc followed by memset, because calloc applies internal optimizations."

int* a = (int*)calloc(n, sizeof(int));   // all zeros
// better than malloc + memset

#52

What is placement new?

Only basics

"A normal new requests memory from the kernel every time, and the switch from user mode to kernel mode is expensive. With placement new, we allocate a large block once, a memory pool, and then construct objects inside it using new (address) Base. The constructor still runs; only the allocation is avoided. Because we constructed the object ourselves, we must call its destructor explicitly, and finally free the whole pool with delete[]."

char* pool = new char[3 * sizeof(Base)];
Base* b = new (pool) Base;   // no new allocation
b->~Base();                  // explicit destructor
delete[] pool;

#73

What is a dangling pointer?

"A dangling pointer is a pointer that still points to memory that has already been freed. For example, if p2 = p1 and we delete p2, then p1 also becomes dangling, because both pointed to the same memory. Accessing it is undefined behavior: it may return a garbage value or crash the program."

int* p1 = new int(100);
int* p2 = p1;
delete p2;        // p1 is now dangling

What is a segmentation fault and how do you debug it?

Only basics

"A segmentation fault occurs when a program accesses memory it is not allowed to, for example by dereferencing a NULL pointer, writing to read-only memory, or overflowing the stack through infinite recursion. The program does not report the line number, so I compile with the -g flag and debug the core dump with gdb ./a.out core, which shows the exact file and line where it crashed."

What happens on out-of-range access in a vector or array?

"Accessing a vector or array out of range with [] does no bounds checking, so it can cause a segmentation fault and crash the program. The .at() function checks the bounds and throws std::out_of_range instead. If we catch that exception with try-catch, the program does not crash and keeps running. In C, we have to write these bounds checks ourselves."

v[100];          // no check → seg fault
try { v.at(100); } catch (...) { }   // handled

#79

What is the difference between arr and &arr?

"arr is the address of the first element and its type is int*, while &arr is the address of the whole array and its type is int (*)[5]. Both print the same address because the array starts where its first element starts. But arr + 1 moves forward by 4 bytes, one element, while &arr + 1 moves forward by 20 bytes, the size of the whole array. So they are not the same."

int arr[5];
arr + 1    // +4 bytes   (int*)
&arr + 1   // +20 bytes  (int (*)[5])

#19

How do you return an array from a function?

"Returning a local array from a function is a bug. The array lives on the function's stack and is destroyed when the function returns; only its address is returned, so the caller gets a dangling pointer, and using it is undefined behavior, often a crash. In general we should never return a pointer or reference to a local variable. There are two simple fixes. First, declare the array static, so it lives until the program ends. Second, allocate it on the heap with new and return the pointer; the memory survives the function, but the caller is then responsible for freeing it with delete[]."

int* bad()  { int a[3];        return a; }  // local: dangling, crash
int* ok1()  { static int a[3]; return a; }  // lives till program ends
int* ok2()  { return new int[3]; }          // heap: caller does delete[]

#18

How do you return a 2D array from a function?

"There are three common ways to return a 2D array. First, allocate it dynamically: an array of row pointers with new int*[n], then each row with new int[n], and return the int**; it survives because it lives on the heap, but the caller must delete each row and then the outer array. Second, make it a static array and return a pointer to its rows, like int (*)[3]; a typedef makes that syntax readable, and the column size must be a constant. Third, wrap the array in a struct and return the struct by value, which copies every element, so it gets slow for large arrays. In practice we usually avoid returning arrays: the caller creates the array and passes it in, and the function just fills it."

int** f();               // dynamic: new int*[n] + new int[n] per row
int (*g())[3];           // static array; typedef int (*Rows)[3];
struct Grid { int a[3][3]; };  Grid h();   // by value, copies all
void fill(int a[][3]);   // usual: caller owns the array

Pointers & references

#4

What is the difference between a reference and a pointer?

"A reference is an alias, another name for an existing variable, so it shares the same memory and address. A pointer is a separate variable that stores an address and has its own memory. A reference must be initialized when it is declared, cannot be null, and cannot be re-bound to another variable later, while a pointer can be left uninitialized, can be nullptr, and can be pointed to something else at any time. A reference is used directly like the variable itself, while a pointer must be dereferenced with *. Pointers also support arithmetic and multiple levels of indirection, like int**, which references do not."

int& ref = a;   // alias: same memory, must init, never null, never re-bound
int* p = &a;    // own memory: can be nullptr, p = &b, *p to use, p++

#20

When do you use a reference over a pointer, and vice versa?

"I prefer references for function parameters and return types. Passing a large object by const reference avoids an unnecessary copy without the pointer syntax. Passing a base class reference avoids object slicing, so virtual functions still work and the function becomes polymorphic. A non-const reference lets a function modify the caller's variable. In some places a reference is mandatory, like the copy constructor parameter, otherwise it would recurse infinitely. I use pointers when the target can be null or needs to change, which is why linked lists, trees and graphs use pointers: a child can be nullptr, and we keep re-pointing nodes while building or traversing them."

void show(const Animal& a);   // big object: no copy, no slicing, virtual works
Animal(const Animal& other);  // copy ctor: reference is mandatory
Node* left = nullptr;         // DS: can be null, can be re-pointed

#13

What is void, and what is a void pointer?

"void means nothing: we use it as the return type of a function that returns nothing, or in the parameter list of a function that takes no arguments, and we cannot declare a variable of type void. A void* is a generic pointer that can hold the address of any data type, except function pointers and, without a cast, const or volatile pointers. We cannot dereference a void* directly, because the compiler does not know the type or size of the data, so we first cast it back to the real type, for example with static_cast<int*>. The most common use is malloc, which returns void*; in C++ we must cast it explicitly. It is also used to write generic functions in C, like the comparator for qsort."

void* v = new int(10);           // generic pointer
cout << *static_cast<int*>(v);   // cast back, then dereference
int* p = static_cast<int*>(malloc(sizeof(int)));   // malloc returns void*

#5

What is a function pointer and where is it used?

"A function pointer stores the address of a function, so we can call that function through it. Its type must match the function exactly: for int add(int, int), we declare int (*fp)(int, int) = &add;, where the brackets around *fp are required, otherwise it declares a function returning int*. We can call it as fp(1, 2) or (*fp)(1, 2), pass it to other functions, return it, and store several in an array, usually with a typedef for readability. The main use is passing behavior to another function, such as a custom comparator: std::sort, or qsort in C, does the sorting, and our function decides how two elements are compared. In C++ we can also pass a lambda or a functor, which is type-safe and usually faster because the comparator can be inlined."

int add(int a, int b);
int (*fp)(int, int) = &add;   // brackets around *fp are required
fp(1, 2);                     // 3
sort(v.begin(), v.end(), cmpDesc);   // pass behavior

#69

What are a class and an object?

"A class is a user-defined data type. C++ provides primitive types like int and char, but for our own needs, such as a Rectangle, we define a class that bundles data, like width and height, with the functions that work on it, like area(). An object is an instance of that class, a variable of that type, such as Rectangle r;, and we call its functions with the dot operator, like r.area()."

class Rectangle { int w, h; public: int area(); };
Rectangle r;     // r is an object

#68

What is abstraction?

"Abstraction means exposing only what is essential and hiding the implementation. Take a UPI payment: the user only sees a Pay button, which is pay(amount). Behind it, the bank debit, GST calculation, logging, notifications and analytics all run, but they are hidden from the user. This keeps the interface simple, and the internal implementation can change without affecting the user. Abstraction hides the implementation, not the data; hiding data is data hiding."

upi.pay(500);

What is data hiding?

"Data hiding means keeping a class's data members private so that users cannot accidentally set invalid values. To modify the data, we provide public functions that validate the input. For example, a Rectangle's width cannot be zero or negative, so setWidth() checks the value before setting it. The purpose is to prevent accidental changes, not to prevent hacking."

class Rectangle {
    int width;                       // private
public:
    void setWidth(int w) { if (w > 0) width = w; }

What is encapsulation?

"Encapsulation means bundling data and the functions that operate on it into a single unit, a class, and keeping the data private so it can only be accessed through public functions. For example, in a BankAccount class, balance is private and can only be changed through deposit() or read through getBalance(), so nobody can modify the balance directly. class BankAccount {

#54

What is the difference between a struct and a class?

"In C++, a struct and a class are almost identical; the only differences are the defaults. In a class, members are private by default, while in a struct they are public by default. Similarly, when inheriting, a class inherits privately by default, and a struct inherits publicly by default. Apart from these defaults, both can have member functions, constructors, inheritance and virtual functions."

class  A { int x; };     // x private
struct B { int x; };     // x public
class  C : B {};         // private inheritance
struct D : B {};         // public inheritance

#75

What is the this pointer? How does it reach a member function?

"this is a hidden pointer that the compiler passes to every non-static member function. It holds the address of the object the function was called on. When I write b.setAge(10), the compiler effectively turns it into setAge(&b, 10), and the function receives that address as Animal* const this, so this->age refers to b's data. That is how one member function works correctly for every object. The pointer itself is constant, so it cannot be made to point to another object. In a const member function its type becomes const Animal* const, so the object's data cannot be modified either; we make getters const to prevent accidental changes and to let the compiler optimize. Static member functions do not get a this pointer because they are not called on an object."

b.setAge(10);   // compiler: setAge(&b, 10)
void setAge(Animal* const this, int age);   // normal
int getAge(const Animal* const this);       // const fn: data fixed too
static void info();                         // no this

#7

What is a friend function and a friend class? Does it break encapsulation?

"A friend function or friend class is given access to a class's private and protected members, even though it is not a member of that class. If I declare a function as a friend, only that function gets access; if I declare a class as a friend, all of its member functions get access. It does not break encapsulation, because the class itself decides who its friends are; an outside function cannot make itself a friend. Friendship also applies only to that class: a friend of Dog does not get access to the private members of its base class Animal. Common uses are giving an admin-like class full rights over another class, writing test code that needs to inspect private state without adding getters, and creating one helper function that works across several classes."

class Employee {
    int salary;
    friend void audit(Employee&);   // only this function
    friend class Admin;             // all of Admin's functions
};   // class decides its friends, so encapsulation holds

Inheritance & polymorphism

#33

What is static vs dynamic binding?

"Binding decides which function a call will execute. In static binding, this is decided at compile time because the compiler already knows the exact function, for example d.speak() on a Dog object. In dynamic binding, it is decided at run time based on the actual object the pointer points to. If speak() is declared virtual in the base class Animal, then calling a->speak() through an Animal* prints "Woof" for a Dog, "Meow" for a Cat and "Moo" for a Cow. Without virtual, the compiler only looks at the pointer type, so Animal::speak() always runs."

Animal* a = new Dog();
a->speak();     // "Woof" only if speak() is virtual

#51

Why do we need a virtual destructor?

"We need a virtual destructor when we delete a derived object through a base class pointer. Without it, the destructor is chosen by the pointer type, so for Animal* a = new Dog(), delete a only runs ~Animal(), and ~Dog() is never called, which causes a memory leak. Making the base destructor virtual ensures the destructor is chosen by the actual object, so ~Dog() runs first and then ~Animal(). Destructors always run in the reverse order of constructors."

Animal* a = new Dog();
delete a;       // ~Dog() runs only if ~Animal() is virtual

#32

What is the diamond problem and how do you solve it?

"The diamond problem occurs in multiple inheritance when two classes inherit from the same base class and a fourth class inherits from both of them. For example, Mammal and WingedAnimal both inherit from Animal, and Bat inherits from both, so Bat ends up with two copies of Animal and accessing age is ambiguous. One workaround is the scope resolution operator, like b.Mammal::age, but both copies still exist in memory. The real solution is virtual inheritance: Mammal and WingedAnimal inherit Animal virtually, so Bat contains only one shared Animal. That shared base is constructed first, by the most derived class, Bat, and both intermediate classes share that single instance. Compilers like GCC implement this with a vptr in each intermediate part that points to a vtable storing the offset of the shared base, which is why the object size increases."

class Mammal       : virtual public Animal {};
class WingedAnimal : virtual public Animal {};
class Bat : public Mammal, public WingedAnimal {};   // one Animal

#50

What is object slicing?

"Object slicing happens when we assign a derived class object to a base class object by value. The base object only has memory for the base class members, so only that part is copied and the derived class's extra members are sliced off. For example, if Dog inherits from Animal and adds tailLength, then Animal a = d; copies only age, and tailLength is lost."

Dog d;
Animal a = d;     // Dog's extra members are sliced off

#44

What does the override keyword do?

"The override keyword was introduced in C++11. We write it on a derived class function to state that it overrides a virtual function from the base class. It does not change the program's behavior, but it has two benefits. First, it makes the code easier to read and test, because anyone can immediately see that the function is an override. Second, it gives a compile-time check: if the signature does not match the base function, for example speak(int) instead of speak(), the compiler reports an error instead of silently creating a new function."

void speak(int) override;

#76

What is function hiding?

"Function hiding happens when a derived class defines a function with the same name as a base class function. All base class functions with that name become hidden in the derived class, even if their parameters are different. For example, if Animal has eat(int) and Dog defines eat(char), then d.eat(1) calls Dog::eat(char), and d.eat() does not even compile. We can fix it by calling d.Animal::eat(1) with the scope resolution operator, or better, by adding using Animal::eat; inside Dog, which brings all the base class overloads into the derived class scope."

class Dog : public Animal {
public:
    using Animal::eat;   // bring back base overloads
    void eat(char c);
};

How do you check whether two objects are of the same class, or the same object?

"To check whether two objects belong to the same class, we use the typeid operator from <typeinfo>: if typeid(obj1) == typeid(obj2), they are of the same class. Two different Dog objects are the same class but not the same object, while a reference to an object has the same address as that object."

typeid(a) == typeid(b)    // same class
&a == &b                  // same object

#12

When should you use operator overloading?

"We should overload an operator only when it makes intuitive sense for the type. Adding two 2D points, two complex numbers or two strings is natural, so overloading + makes the code easier to read. Adding two rockets or two tables has no obvious meaning, so even though the language allows it, it would only confuse the reader. The syntax is a function named operator followed by the symbol, for example Point operator+(const Point& other). When it is a member function, it is called on the left operand, so p1 + p2 becomes p1.operator+(p2), and it returns a new Point."

Point operator+(const Point& p2);   // p1 + p2 -> p1.operator+(p2)
p1 + p2;        // makes sense: (2,3)+(4,5) = (6,8)
str + "Nuts";  // makes sense
rocket + table; // allowed, but confusing: don't

#62

How do you overload pre- and post-increment operators?

"Both are overloaded as operator++, so C++ uses a dummy int parameter to tell them apart: T& operator++() is pre-increment and T operator++(int) is post-increment; the int is never used, it is only a tag. Pre-increment increments the object and returns *this by reference, so the caller sees the new value. Post-increment first saves a copy of the current object, increments the real object, and returns the saved copy by value, so the caller sees the old value. It must return by value because the copy is a local variable, and returning a reference to it would dangle. Because post-increment creates that extra copy, pre-increment is more efficient for class types, which is why we write ++it in loops."

Counter& operator++()    { ++count; return *this; }   // ++c: new value, by ref
Counter  operator++(int) { Counter t = *this; ++count; return t; }  // c++: old copy, by value
// int = dummy tag; pre is faster (no copy)

Constructors & copying

#22

When must you use an initializer list?

"An object is built in two steps: first all members are constructed, which is where the initializer list runs, and only then does the constructor body execute. Anything that must have a value at the moment it is created therefore needs the initializer list. That covers const members and reference members, since they cannot be assigned later; member objects whose class has no default constructor; base class constructors that need arguments; and parameters with the same name as a member, where age = age in the body would just assign the parameter to itself. It is also more efficient, because the member is constructed once with the right value instead of being default-constructed and then assigned."

Dog(int a, Owner x, int& r)
    : Animal(a), o(x), ref(r), legs(4) {}
// base ctor, no-default-ctor member, reference, const

#49

What is an explicit constructor?

"The explicit keyword prevents implicit calls to a constructor. If a class has a constructor that takes a single argument, such as Animal(int), the compiler can use it as an automatic conversion: Animal a = 20; or passing 30 to a function that expects an Animal both compile, because the compiler silently calls Animal(20) or Animal(30). That can hide bugs. Marking the constructor explicit turns those into compile-time errors, so the constructor can only be called when we write it explicitly, like Animal a(20) or printAge(Animal(30))."

explicit Animal(int a);
Animal a = 20;      // error
Animal b(20);       // fine

#55

Why is the size of an empty class 1 byte?

"In C++, the size of an empty class or struct is 1 byte, not 0, because every object must have a unique address. If the size were zero, two objects like a1 and a2 could end up at the same address and could not be told apart, so the compiler gives each empty object the smallest possible size, one byte. If the class has a member, such as an int, no extra byte is added: the size is just 4, because the member already gives each object its own address."

class Animal {};
sizeof(Animal);     // 1  (every object needs a unique address)

#81

Does a static data member occupy space in the class object?

"No, a static data member does not occupy space inside the object, so sizeof of the class does not change. It is stored separately, like a global variable, and there is only one copy for the whole class. Declaring it inside the class only says that it exists; it must also be defined once outside the class, otherwise using it gives an 'undefined reference' linker error. If no value is given in the definition it is zero-initialized, just like a global. Its lifetime is the entire program, and the class acts as a wrapper around the name, so we access it as Dog::legs."

class Dog { int age; static int legs; };
sizeof(Dog);        // 4: static not inside the object
int Dog::legs;      // must define once; default 0, like a global
Dog::legs;          // one copy, lives for the whole program

#58

Why does the copy constructor take its argument by const reference?

"A copy constructor takes its argument by reference to avoid infinite recursion. If it took the argument by value, passing the object would require making a copy, which would call the copy constructor again, and so on forever. The compiler actually rejects that with an error. We make the reference const so the copy constructor cannot accidentally modify the original object; it only needs to read from it. So the standard signature is Animal(const Animal& obj)."

Animal(const Animal& obj);   // correct
Animal(Animal obj);          // error: infinite recursion

#72

What is the difference between a shallow copy and a deep copy?

"A shallow copy copies each member as it is, so for a pointer member only the address is copied, and both objects end up pointing to the same memory. Changing one changes the other, and when one object's destructor deletes that memory, the other is left with a dangling pointer, which can lead to a double free. A deep copy allocates new memory for the copy and copies only the value, so each object owns its own memory. The compiler-generated copy constructor does a shallow copy, which is fine for simple members, but if a class owns dynamically allocated memory through a pointer, we must write our own copy constructor and copy assignment operator to do a deep copy."

Animal(const Animal& rhs) {
    weight = new int(*rhs.weight);   // deep copy: new memory
}

#40

Why does the copy assignment operator return a reference?

Parked

"The copy assignment operator returns a reference to *this to support chained assignment, so that a class behaves just like built-in types such as int. If it returned by value, b2 = b3 would return a temporary copy, so in (b2 = b3) = b1 the second assignment would modify that temporary instead of b2, and b2 would keep the wrong value. Returning by value also creates unnecessary temporary objects. Returning a reference means the result of the assignment is the object itself, so every chained assignment works correctly."

Animal& operator=(const Animal& rhs) {
    age = rhs.age;
    return *this;
}

How do you prevent an object from being copied?

Parked

"To prevent an object from being copied, for example in a Singleton, we have to block both the copy constructor and the copy assignment operator. There are three ways. First, declare both as private, so code outside the class cannot call them. Second, inherit from a helper class like StopCopy whose copy constructor and assignment operator are private; since copying a derived object also requires copying its base part, the derived class cannot be copied either. Third, and the cleanest since C++11, mark both functions with = delete, which tells the compiler not to generate them. In all three cases, objects can still be created and used normally; they just cannot be copied."

Animal(const Animal&) = delete;
Animal& operator=(const Animal&) = delete;

#46

Why was vector introduced?

"Vector was introduced to fix the problems of raw C arrays. A C array has a fixed size known at compile time; making it dynamic means manual new, copying and delete[], which is error-prone and leaks memory if we forget. An array also decays to a pointer when passed to a function, so its size is lost, and indexing has no bounds checking. A vector grows and shrinks at runtime, manages its own memory and frees it in its destructor, always knows its size, offers bounds-checked access with at(), and works with STL algorithms, while keeping the same contiguous storage and speed as an array."

int arr[5];        // fixed size, decays to pointer, no bounds check
vector<int> v;     // grows at runtime, frees itself (RAII)
v.size(); v.at(10); // knows size; at() throws out_of_range

#6

How does a vector work internally?

"A vector is a dynamic array. It stores its elements in one contiguous block on the heap, and the vector object itself only holds a pointer to that block, the size and the capacity. Size is how many elements it has; capacity is how many it can hold before it needs more memory. When push_back finds the vector full, it allocates a bigger block, typically double the capacity in GCC, copies or moves the existing elements into it, and frees the old block. Because the capacity grows geometrically, reallocation is rare and push_back is amortized O(1). If we know the final size, reserve() avoids repeated reallocations."

// heap: one contiguous block; object = {pointer, size, capacity} (24 bytes)
v.push_back(x);   // full? new block (2x in GCC), copy, free old
// capacity 1,2,4,8,16 -> amortized O(1)
v.reserve(100);   // avoid repeated reallocation

#45

What are the drawbacks of vector?

"Vector's drawbacks come from its contiguous storage. When it runs out of capacity it has to reallocate and copy every element, which is costly for large vectors; reserve() helps when the size is known. Reallocation also invalidates existing pointers, references and iterators to its elements. Inserting or erasing at the front or in the middle is O(n), because the following elements must be shifted, and there is no push_front. Capacity is usually larger than size, so some memory is wasted, and a very large vector needs one big contiguous block. For frequent front insertions a deque fits better, and for frequent middle insertions a list."

// full -> reallocate + copy all elements
int* p = &v[0]; v.push_back(5);   // p may dangle (iterator invalidation)
v.insert(v.begin(), 0);           // O(n) shift; no push_front
// capacity > size wastes memory; needs one big block

Why is 'using namespace std' considered bad?

"using namespace std; pulls every name from the standard library into the current scope, and std contains thousands of names like count, max and find. If my own code uses the same name, I get ambiguity errors or, worse, the wrong function silently chosen, and code can break later when the library adds new names. It is especially bad in a header file, because every file that includes the header gets the directive too. It is better to write std:: explicitly or bring in only specific names with using std::cout;. In small programs or competitive programming it is usually acceptable."

using namespace std;
int count = 0;
count++;   // error: reference to 'count' is ambiguous
// never in headers; prefer std::cout or using std::cout;

What is C++?

C++ is a compiled, multi-paradigm language built on top of C. It gives the speed and low-level memory control of C, together with high-level abstractions like object-oriented programming and templates. Its core design idea is zero-overhead abstraction: you do not pay for features you do not use. That is why it is used for performance-critical software such as game engines, databases, browsers and simulation tools.

What is RAII?

RAII stands for Resource Acquisition Is Initialization. The idea is to tie a resource's lifetime to an object's lifetime: the constructor acquires the resource and the destructor releases it. C++ guarantees that a stack object's destructor runs when it goes out of scope, whether the function returns normally, returns early or exits through an exception. During an exception, stack unwinding destroys all local objects in reverse order. So resources can never leak. The standard library is built on this: vector and string for memory, unique_ptr and shared_ptr for heap objects, fstream for files, and lock_guard for mutexes, which prevents a lock from staying held after an exception. The common pitfalls are creating the RAII object itself with raw new, and copying a class that owns a raw resource, which causes a double free; we prevent that by deleting the copy operations, implementing a deep copy, or better, following the Rule of Zero with unique_ptr or vector members. Compared to a garbage collector, RAII is deterministic and works for any resource, not just memory.

{
    std::lock_guard<std::mutex> lock(m);   // lock()
}                                          // unlock(), even on exception
Buffer* p = new Buffer;   // trap: no } owns it -> use make_unique

What are smart pointers? unique_ptr vs shared_ptr?

Smart pointers are RAII wrappers around raw pointers: they delete the object in their destructor, so we avoid leaks, double deletes and dangling pointers. unique_ptr models exclusive ownership. It cannot be copied, only moved, and it has no overhead over a raw pointer, so it is the default choice. shared_ptr models shared ownership: it keeps a reference count in a control block, copying increments the count, destruction decrements it, and the object is deleted when the count reaches zero. Its weakness is cycles: if two objects hold shared_ptrs to each other, the counts never reach zero and they leak. weak_ptr solves this: it observes a shared_ptr-managed object without increasing the count, and we call lock() to get a shared_ptr if the object is still alive. We should create them with make_unique and make_shared, and never create two shared_ptrs from the same raw pointer.

auto u = make_unique<Dog>("Tommy");  auto u2 = move(u);   // u = nullptr
auto s = make_shared<Dog>("Bruno");  auto s2 = s;          // use_count() = 2
weak_ptr<Dog> w = s;  if (auto p = w.lock()) { ... }      // no count++
u2.reset();  // delete     u2.release();  // give up, no delete
