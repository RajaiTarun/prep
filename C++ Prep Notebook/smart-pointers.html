1. Problem: raw pointer mein dikkat kya hai?

void f() {
    Car* c = new Car("BMW");
    c->drive();
    if (error) return;     // delete bhool gaye → leak
    riskyFunction();       // exception aaya → delete kabhi nahi chalega
    delete c;
}

Raw pointer ke saath teen bugs aate hain: leak, double free, dangling. Inse badi problem ek aur hai: function signature Car* getCar(); se pata hi nahi chalta ki delete kisko karna hai, tumhe ya function ko. Raw pointer ownership nahi batata.

2. Smart pointer asal mein hai kya?

Definition

Smart pointer = ek chhoti si class jo raw pointer ko pakad ke rakhti hai, aur uske destructor mein delete likha hota hai. Ye seedha RAII hai, jahan resource heap memory hai.

template <typename T>
class MySmartPtr {
    T* ptr;
public:
    MySmartPtr(T* p) : ptr(p) { cout << "Pakda\n"; }
    ~MySmartPtr() { cout << "delete kiya\n"; delete ptr; }   // RAII
    T& operator*()  { return *ptr; }    // *p kaam kare
    T* operator->() { return ptr; }     // p->x kaam kare
};

struct Point { int x = 3, y = 4; };

int main() {
    {
        MySmartPtr<Point> p(new Point());
        cout << p->x << " " << (*p).y << "\n";
    }
    cout << "scope khatam\n";
}
Pakda
3 4
delete kiya
scope khatam
  1. Destructor ki wajah se delete apne aap hua (RAII).
  2. * aur -> overload kiye (operator overloading), isliye ye normal pointer jaisa use hota hai.
Isme ek bug hai

MySmartPtr<Point> q = p; likha toh shallow copy hogi aur double free hoga (RAII Trap 2). Standard library ne ise do tareekon se solve kiya: unique_ptr (copy band) aur shared_ptr (counter).

4. unique_ptr: ek hi malik

unique_ptr<Car> a = make_unique<Car>("BMW");   // make_unique (C++14) khud new karta hai
a->drive();                                    // normal pointer jaisa
unique_ptr<Car> b = a;                         // ❌ compile error
unique_ptr<Car> b = move(a);                   // ✅ ownership a se b ko

Copy ka actual compiler error:

error: use of deleted function 'std::unique_ptr<_Tp, _Dp>::unique_ptr(const std::unique_ptr<_Tp, _Dp>&)'

"deleted function" = wahi = delete jo humne FileHandler mein kiya tha. Do malik matlab double free.

std::move khud kuch move nahi karta. Ye bas compiler ko bolta hai: "a ka maal le jaane ki permission hai." Phir b pointer le leta hai aur a ko nullptr set kar deta hai.

Poora example

struct Car {
    string name;
    Car(string n) : name(n) { cout << "Car " << name << " bani\n"; }
    ~Car() { cout << "Car " << name << " destroy\n"; }
    void drive() { cout << name << " chal rahi hai\n"; }
};

unique_ptr<Car> factory() { return make_unique<Car>("Factory"); }
void takeOwnership(unique_ptr<Car> c) { cout << "Function ke paas: " << c->name << "\n"; }
void justUse(Car* c)                  { cout << "Sirf use: " << c->name << "\n"; }

int main() {
    unique_ptr<Car> a = make_unique<Car>("BMW");
    a->drive();
    unique_ptr<Car> b = move(a);
    cout << "a null hai? " << (a == nullptr ? "haan" : "nahi") << "\n";

}

5. shared_ptr: kai malik, aakhri wala band kare

Reference counting: ek counter rakho, "abhi kitne log is object ke malik hain?" Copy hua → +1. Koi shared_ptr destroy/reset hua → −1. Counter 0 → object delete. Analogy: room mein jo aakhri insaan bahar nikle, wo light band kare.

int main() {
    shared_ptr<Car> a = make_shared<Car>("Audi");
    cout << "count = " << a.use_count() << "\n";
    {
        shared_ptr<Car> b = a;          // copy allowed!
        cout << "copy ke baad count = " << a.use_count() << "\n";
        shared_ptr<Car> c = a;
        cout << "ek aur copy, count = " << a.use_count() << "\n";
    }
    cout << "b, c scope se bahar, count = " << a.use_count() << "\n";
    a.reset();
    cout << "a.reset() ke baad\n";
}

Counter rehta kahan hai? Control block

Counter kisi ek shared_ptr ke andar nahi reh sakta (sab ko same number dikhna chahiye). Isliye heap pe ek alag control block banta hai, aur har shared_ptr do pointer rakhta hai.

sizeof(shared_ptr<Car>) = 16      ← do pointers (object + control block)

make_shared kyun?

  • shared_ptr<Car>(new Car(...)) → do heap allocations (ek Car, ek control block).
  • make_shared<Car>(...) → ek allocation, dono saath mein. Fast aur cache-friendly, aur code mein raw new nahi.

Keemat

unique_ptr free hai, par shared_ptr ki keemat hai: size double (16 bytes), control block ki extra memory, aur counter atomic hota hai (thread-safe, par normal +1/−1 se slow).

Depth point

Counter thread-safe hai, par object nahi. Do threads ek hi Car ko modify karein toh mutex chahiye hi.

6. Cycle problem aur weak_ptr

struct B;
struct A { shared_ptr<B> b; ~A() { cout << "~A\n"; } };
struct B { shared_ptr<A> a; ~B() { cout << "~B\n"; } };

int main() {
    {
        auto a = make_shared<A>();
        auto b = make_shared<B>();
        a->b = b;  b->a = a;              // ek doosre ko pakda
        cout << "a count = " << a.use_count() << ", b count = " << b.use_count() << "\n";
    }
    cout << "scope khatam (koi destructor nahi chala?)\n";
}
a count = 2, b count = 2
scope khatam (koi destructor nahi chala?)     ← ~A, ~B kabhi nahi → leak

Fix: ek taraf ka link weak_ptr kar do. weak_ptr object ko point karta hai par strong count nahi badhata.

struct B { weak_ptr<A> a; ~B() { cout << "~B\n"; } };   // sirf ye line badli
a count = 1, b count = 2       ← A ka count ab sirf 1
lock() se A mila, count abhi = 2
~A
~B                              ← dono destroy, leak khatam
scope khatam

weak_ptr ko use kaise karte hain

weak_ptr ko direct -> se use nahi kar sakte, kyunki ho sakta hai object mar chuka ho. Pehle lock() karo:

if (auto sp = w.lock()) {     // object zinda hai → shared_ptr mila
    sp->doSomething();
} else {                      // object mar chuka → nullptr mila
    ...
}
expired? 0                          ← object zinda
s gaya, expired? 1, lock null? 1    ← object gaya, weak_ptr ko pata chal gaya

Raw pointer ko kabhi pata nahi chalta ki object mar gaya (dangling), par weak_ptr ko chalta hai. Real use: tree mein child → parent link, observer pattern, cache.

8. Kaunsa choose karein?

9. Interview mein kaise bolo

30-second answer

"Smart pointers RAII wrappers hain jo heap memory ki ownership manage karte hain. Inka destructor apne aap delete karta hai, toh leak, double free aur dangling pointer jaise bugs khatam ho jaate hain. unique_ptr exclusive ownership deta hai: copy nahi hota, sirf move hota hai, aur iska size raw pointer jitna hai, toh zero overhead. shared_ptr shared ownership deta hai reference counting se, aur aakhri owner jaate hi object delete hota hai. weak_ptr non-owning hai aur shared_ptr cycles todne ke liye use hota hai. Mera default unique_ptr hai, shared_ptr sirf tab jab sach mein shared ownership chahiye."

"Mujhe smart pointers ka sabse bada fayda safety se zyada readability lagta hai. Self-check

1. unique_ptr<Car> b = a; compile kyun nahi hota? Fix kya, aur uske baad a ka kya hoga?

Copy constructor = delete hai, kyunki do owners double delete karenge. Fix: unique_ptr<Car> b = move(a);. Uske baad a nullptr hai.

2. shared_ptr ka sizeof 16 kyun, jabki unique_ptr ka 8?

shared_ptr do pointers rakhta hai: ek object ka, ek control block (ref count) ka. unique_ptr sirf ek raw pointer hai.

3. Do objects ek doosre ko shared_ptr se pakde hain. Kya hoga, fix?

Cycle: locals jaane ke baad bhi dono ka count 1 rehta hai, kabhi 0 nahi, toh destructors nahi chalte → leak. Fix: ek link weak_ptr bana do.

4. reset() vs release()?

reset() object delete karta hai aur pointer null karta hai. release() delete nahi karta, sirf ownership chhod ke raw pointer return karta hai; ab delete tumhari zimmedari.

5. Same raw pointer se do shared_ptr banaye. Kya hoga, kyun?

Do alag control blocks bante hain, dono ka count 1. Dono khud ko akela malik maante hain aur dono delete karte hain → double free crash.
