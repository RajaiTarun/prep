1.1 C struct vs C++ struct

C mein struct sirf data ka dabba hai. 2 cheezein yaad rakho:

  1. Type ke aage struct likhna padta hai (ya typedef karo).
  2. Andar function nahi likh sakte, aur public/private bhi nahi hote.
// C
struct Point { int x, y; };
Point p;                        // ❌ C mein error
struct Point p = {1, 2};       // ✅ struct likhna padega

typedef struct { int x, y; } Pt;
Pt q = {3, 4};                  // ✅ typedef ke baad seedha naam

1.2 -> vs .

1.3 Padding (quick recap)

Detail #1, #77 mein. Yaad rakho: har member apne size ke multiple wale address pe baithta hai, beech mein khaali bytes (padding) aa jaate hain. Members bade se chhote order mein rakho, padding kam:

struct Bad  { char a; int b; char c; };      // 1 + 3 pad + 4 + 1 + 3 pad
struct Good { int b; char a; char c; };      // 4 + 1 + 1 + 2 pad
struct Mix  { char a; double d; int i; };

Bad=12 Good=8 Mix=24 Mix2=16

1.4 Struct mein pointer: copy = shallow copy

Struct copy karo toh har member ki value copy hoti hai. Member pointer hai toh sirf address copy hota hai, memory nahi. Dono struct same memory pe:

struct Buf { int* data; };

Buf a;  a.data = (int*)malloc(4 * sizeof(int));  a.data[0] = 5;
Buf b = a;                 // sirf pointer copy hua
b.data[0] = 100;           // b ne badla...
free(a.data);
free(b.data);              // ❌ wahi memory dobara
a.data[0] = 100  (b ne badla, a pe asar)
a.data == b.data ? 1
free(): double free detected in tcache 2

2 problems: ek ne badla toh doosre pe asar, aur do baar free = crash. Ye wahi RAII Trap 2 hai. C++ mein fix: deep copy (Rule of Three, #58), copy = delete, ya pointer ki jagah vector.

1.5 Self-referential struct (linked list)

Struct jo apne hi type ka pointer rakhe:

struct Node {
    int val;
    Node* next;             // ✅ pointer: hamesha 8 bytes
};

Node c{30, nullptr}, b{20, &c}, a{10, &b};
for (Node* p = &a; p != nullptr; p = p->next)
    cout << p->val << " -> ";
10 -> 20 -> 30 -> nullptr
sizeof(Node) = 16        (4 int + 4 padding + 8 pointer)

Pointer kyun, Node kyun nahi? Node next; likha toh Node ke andar poora Node, uske andar phir Node... size infinite. Compiler mana kar deta hai:

struct Node { int val; Node next; };  →  error: field 'next' has incomplete type 'Node'

Pointer ka size fixed hai (8 bytes), chahe wo kisi pe bhi point kare. Isliye chalta hai.

1.7 C mein apna Vector (realloc ke saath)

Ye ek senior ko notepad pe likhwaya gaya tha. Idea bilkul C++ vector jaisa (#6): data ka pointer + size + capacity, full ho toh double.

typedef struct {
    int* data;
    size_t size, cap;
} Vector;

void vec_init(Vector* v) { v->data = NULL; v->size = 0; v->cap = 0; }

void vec_push_back(Vector* v, int x) {
    if (v->size == v->cap) {                                  // jagah khatam
        size_t newCap = (v->cap == 0) ? 1 : v->cap * 2;       // double
        int* p = realloc(v->data, newCap * sizeof(int));     // bada block, purana data copy
        if (p == NULL) { printf("out of memory\n"); exit(1); }
        v->data = p;
        v->cap = newCap;
    }
    v->data[v->size++] = x;                                   // daalo, size badhao
}

void vec_free(Vector* v) { free(v->data); v->data = NULL; v->size = v->cap = 0; }

// main
Vector v;
vec_init(&v);
for (int i = 1; i <= 5; i++) vec_push_back(&v, i * 10);
vec_free(&v);
push 10: size=1 cap=1
push 20: size=2 cap=2
push 30: size=3 cap=4
push 40: size=4 cap=4
push 50: size=5 cap=8
10 20 30 40 50
Notepad pe yaad rakhne wali 4 baatein
  1. Function ko Vector* do (by value doge toh copy badlegi, asli nahi).
  2. realloc(NULL, n) = malloc(n), toh pehli baar alag case nahi chahiye.
  3. realloc ka result pehle alag variable (p) mein lo. Fail hua toh NULL aata hai; seedha v->data mein daala toh purana pointer kho jaata (leak).
  4. free ke baad pointer NULL kar do (dangling se bachao).
Interview mein

"In C, a struct is just a group of data members: it cannot have member functions or access specifiers, and we must write struct Point or use a typedef. In C++, a struct is the same as a class except that members and inheritance are public by default, while a class defaults to private. We access members with . on an object and -> on a pointer, where p->x is shorthand for (*p).x; *p.x fails because . binds tighter than *. Because of alignment, the compiler inserts padding, so ordering members from largest to smallest reduces the size. Copying a struct that holds a raw pointer copies only the address, a shallow copy, which leads to shared data and double frees. A struct can refer to its own type only through a pointer, as in a linked-list node, since a member of its own type would have infinite size. Large structs should be passed by pointer or const reference instead of by value to avoid the copy."

2.1 Precedence: *p++, ++*p, *++p, (*p)++

Do rule yaad rakho: postfix (x++, [], ->, .) sabse upar. Prefix (++x, *, &) ek level neeche aur right-to-left padhte hain. Toh *p++ = *(p++) (value pehle, pointer baad mein) aur ++*p = ++(*p) (value badhti hai).

int a[] = {10, 20, 30, 40};
int* p = a;

printf("%d\n", *p++);      // 10 print, phir p aage (a[1])
printf("%d\n", *p);        // 20
printf("%d\n", ++*p);      // pehle *p (a[1]) ko ++ : 21
printf("%d\n", *++p);      // pehle p aage (a[2]), phir 30
printf("%d\n", (*p)++);    // 30 print, phir a[2] = 31
printf("%d %d %d %d\n", a[0], a[1], a[2], a[3]);

2.2 Arithmetic: p + 1 kitna aage?

p + n = n × sizeof(*p) bytes aage. q - p = beech mein kitne elements (bytes nahi). Dono pointer ek hi array ke hone chahiye.

2.3 sizeof pointer vs sizeof reference

Pointer: sizeof kisi bhi pointer ka fixed hota hai: 8 bytes (64-bit system) aur 4 bytes (32-bit system). Isse farak nahi padta ki wo char* hai, int*, double* ya function pointer: pointer sirf ek address rakhta hai, aur address ka size machine pe depend karta hai (64-bit address = 8 bytes), pointed type pe nahi.

2.6 void*: generic pointer

2.8 Double pointer: function mein list ka head badalna

C/C++ mein sab kuch by value jaata hai. Pointer ko function mein bhejoge toh pointer ki copy badlegi. Asli pointer badalna hai toh uska address (Node**) bhejo.

void pushWrong(Node* head, int v) { head = new Node{v, head}; }       // head ki COPY badli
void pushRight(Node** head, int v) { *head = new Node{v, *head}; }    // asli head badla
void print(Node* h) { for (; h; h = h->next) printf("%d ", h->val); printf("\n"); }

Node* head = nullptr;

Part 1: Lambda Expressions

3.1 Lambda Expression kya hai?

Imagine tumhare paas ek function hai jo sirf ek particular jagah use hona hai. Normally tum function define karoge:

int add(int a, int b) {
    return a + b;
}

Par agar mujhe ye function sirf ek baar use karna hai, toh alag se function banane ki kya zarurat? Yahin aata hai Lambda Expression.

Lambda basically ek anonymous function hai (bina naam ka function) jise tum wahin define kar sakte ho jahan chahiye.

Syntax:

[capture](parameters) -> return_type {
    // function body
};
PartMeaning
[]Capture clause
(parameters)Function arguments
-> return_typeReturn type (kai cases mein optional)
{}Function body

Example 1: Basic Lambda

auto add = [](int a, int b) {
    return a + b;
};

cout << add(10, 20);

Dhyan do:

  • [ ] ka matlab hum kuch capture nahi kar rahe.
  • add lambda ko store karta hai.
  • auto khud uska type nikaal leta hai.
  • Hum use bilkul normal function ki tarah call karte hain.
Interview answer (English)

"A lambda expression in C++ is an anonymous function that can be defined inline. It is useful for writing short, local functions without explicitly defining a separate function. Lambdas can also capture variables from their surrounding scope."

3.2 Capture Clause: VERY IMPORTANT

Bro, ye lambdas ka shayad sabse important part hai. Maan lo:

int x = 10;

auto print = []() {
    cout << x;
};

print();
error: 'x' is not captured

Kya ye chalega? Nahi! Kyunki lambda surrounding scope ke local variables ko apne aap access nahi kar sakta. Iske liye capture clause chahiye.

A. Capture by value [=]

Lambda x ki copy le leta hai. Socho: lambda ke paas x ki apni copy hai. Ab dekho:

int x = 10;

auto print = [=]() {
    cout << x;
};

x = 50;

print();
10

Kyun 10? Kyunki lambda ne banate waqt ki value capture kar li thi. Baad mein x badla toh lambda ko farak nahi pada.

B. Capture by reference [&]

int x = 10;

auto print = [&]() {
    cout << x;
};

x = 50;

print();
50

Kyun 50? Kyunki lambda ke paas original variable ka access hai, alag copy nahi.

Interview answer (English)

"The capture clause specifies how a lambda accesses variables from its enclosing scope. Variables can be captured by value, which creates copies, or by reference, which allows access to the original variables. We can also capture specific variables individually."

Important interview points
  • [=] = copy (snapshot, banate waqt ki value). [&] = original (hamesha taaza value).
  • By-value copy const hoti hai: badalne ke liye mutable. Original phir bhi nahi badalta.
  • Reference capture mein dhyan: variable mar gaya (scope se bahar) toh lambda dangling reference rakhega (bonus).

3.3 Lambda with STL: OA ke liye extremely important

Yahan lambdas sach mein kaam aate hain. Maan lo array ko descending sort karna hai. Normally: sort(arr.begin(), arr.end(), greater<int>());. Par custom condition chahiye, jaise absolute values ke hisaab se sort:

vector<int> arr = {-5, 2, -1, 4, -3};

sort(arr.begin(), arr.end(), [](int a, int b) {
    return abs(a) < abs(b);
});

for (int v : arr) cout << v << " ";
-1 2 -3 4 -5

Lambda yahan custom comparator ka kaam karta hai. Comparator kaise kaam karta hai? return a < b ka matlab: a ko b se pehle aana chahiye. Condition true hai toh a pehle aata hai b se.

Lambda ke saath use kar sakte ho: sort(), stable_sort(), count_if(), find_if(), remove_if(), for_each().

Example: count_if()

vector<int> arr = {1, 2, 3, 4, 5, 6};

int cnt = count_if(arr.begin(), arr.end(), [](int x) {
    return x % 2 == 0;
});

cout << cnt;
3
Interview answer (English)

"Lambdas are commonly used with STL algorithms as custom comparators or predicates. They help us write concise and readable logic without creating separate function objects."

Important interview points
  • Comparator mein < (ya >) use karo, <= nahi: sort ko strict weak ordering chahiye, warna undefined behaviour / crash ho sakta hai.
  • sort comparator = 2 arguments, bool return. count_if / find_if predicate = 1 argument, bool return.
  • for_each ke saath [&total] se bahar ka variable badal sakte ho (sum, count).

Part 2: Functors

3.4 Functor kya hai?

Bro, ye concept actually kaafi simple hai. Functor ek class ya struct hai jiske objects ko function ki tarah call kiya ja sakta hai. Kaise? () operator ko overload karke.

class Add {
public:
    int operator()(int a, int b) {
        return a + b;
    }
};

Add obj;

cout << obj(10, 20);
30

Dhyan do: obj(10, 20);. Normally obj ek object hai, par hum use function ki tarah call kar rahe hain! Ye isliye possible hai kyunki humne function call operator () overload kiya.

Yaad kaise rakhein?

  • Normal function → add(10, 20)
  • Functor → obj(10, 20)
  • Lambda → add(10, 20)

Teeno ko similar call kar sakte hain, par implementation alag hai.

Interview answer (English)

"A functor, also known as a function object, is an object of a class or struct that overloads the function call operator operator(). This allows the object to be invoked like a regular function."

3.5 Functors kyun chahiye?

Ek important advantage: functors state maintain kar sakte hain.

class Counter {
    int count = 0;

    void operator()() {

};

Dekha kya hua? Object ko apni pichhli state yaad hai. Ye tab kaam aata hai jab callable object ko calls ke beech kuch data yaad rakhna ho.

Interview answer (English)

"Functors are useful when we need callable objects that maintain state. Unlike ordinary functions, they can store data as member variables and preserve that state across multiple invocations."

Important interview points
  • Functor = class + operator(). State member variables mein rehti hai.
  • STL mein bahut use: greater<int>, less<int> standard functors hain (sort(..., greater<int>()), priority_queue).
  • Trap: STL algorithms functor ko by value lete hain, toh algorithm ke baad tumhare original object mein state nahi dikhti (bonus).

Part 5: Function Pointers

3.8 Function Pointer kya hai?

Normally jab hum function call karte hain:

int add(int a, int b) {
    return a + b;
}

int main() {
    cout << add(10, 20);
}

Par kya pata hai, functions ka bhi memory address hota hai? Variables ki tarah hum function ka address bhi ek pointer mein store kar sakte hain. Wahi Function Pointer karta hai: function ka address store karta hai aur pointer ke through us function ko call karne deta hai.

Syntax:

return_type (*pointer_name)(parameter_types);

Example:

int add(int a, int b) {
    return a + b;

int (*ptr)(int, int) = add;

30

Tod ke samjho: int (*ptr)(int, int);

  • int → function ka return type.
  • *ptr → function ka pointer.
  • (int, int) → function do integer arguments leta hai.
Important: *ptr ke bracket matter karte hain!

Bracket ke bina int *ptr(int, int); ek function declare karta hai jo int* return karta hai, function pointer nahi:

"A function pointer is a pointer that stores the address of a function. It allows us to invoke a function indirectly through the pointer. The pointer's type must match the function's return type and parameter types."

3.12 Important interview questions (Part 3 of the notes)

Q1. Can a function pointer store a lambda?

A non-capturing lambda can be converted to a compatible function pointer. A capturing lambda cannot be converted to an ordinary function pointer.

Q2. Can a functor maintain state?

Yes. A functor can maintain state using member variables, which persist across multiple function calls.

Q3. What is the difference between a function pointer and a functor?

A function pointer stores the address of an existing function, whereas a functor is an object that overloads the function call operator.

Q4. Are lambdas internally implemented using functors?

Essentially, yes. The compiler generates a unique unnamed closure type for every lambda expression. This type has an overloaded function call operator. (Captures become its data members; see the sizeof demo in the bonus section.)

Q5. Which one would you prefer?

It depends on the use case:

  • Function pointer for simple callbacks and when a plain function pointer interface is required.
  • Lambda for concise inline logic and capturing local variables.
  • Functor for reusable callable objects with state and more complex behavior.
Function pointers: yaad rakhne wali baatein
  • Function ka address store karta hai: ret (*p)(params). Bracket zaroori.
  • Runtime pe decide karne ke liye (ek pointer, alag functions) aur callbacks ke liye (function ko argument ki tarah pass).
  • State nahi rakhta. State chahiye toh lambda (capture) ya functor (members).
  • Bina capture wala lambda → function pointer ban sakta hai. Capture wala nahi.

Interview mein (ek saath, bonus ke saath)

"A lambda is an unnamed function object written in place, and the compiler turns it into a class whose data members are the captured variables and whose operator() is const unless I write mutable. A functor is the same idea written by hand: a class with operator() that can keep state. Capture by value takes a copy when the lambda is created; capture by reference sees later changes but can dangle. Inside a member function [=] captures this, not the members. I use both with STL algorithms as comparators and predicates. A lambda without captures converts to a function pointer, and std::function can hold any callable at the cost of type erasure."

1. Lambda kya hai aur compiler uska kya banata hai?
Naamless function object. Compiler ek class banata hai: captures = members, body = const operator().
2. [=] vs [&]?
[=] banate waqt ki copy (snapshot), [&] reference (taaza value, par dangling ka khatra).
3. mutable kyun chahiye?
operator() default const hai, toh by-value copy badal nahi sakte. mutable se badal sakte, aur state call-to-call yaad rehti.
4. Functor vs lambda?
Dono callable objects. Lambda inline aur chhota; functor ek poori class (reuse, naam). Dono state rakh sakte, aur dono STL algorithms mein chalte.
5. Functor kyun use karte hain?
Callable object jo member variables mein state rakhe aur calls ke beech yaad rakhe.
6. Lambda ko function pointer mein kab badal sakte hain?
Jab koi capture na ho. Capture wala lambda ek object hai jisko data chahiye.
7. Member function mein [=] kya capture karta hai?
this pointer, members ki copy nahi. Object mara toh dangling. Fix: [v = v] ya C++17 [*this].

Interview mein

"static has four uses. A static local is initialized once and keeps its value between calls, stored in the data segment, and since C++11 its initialization is thread-safe. 1. Static local variable kab init hota hai, aur kitni baar?
Pehli baar control wahan pahunchne pe, sirf ek baar. Baad mein value yaad rehti hai.
2. File-level static aur static data member mein farak?
File-level: internal linkage (sirf us file mein). Data member: class ka ek shared copy.
2b. Static data member sizeof(class) mein count hota hai?

Nahi. Wo class ka shared variable hai, data segment mein, object ke andar nahi. Sirf non-static members (aur vptr) size badhate hain. Sirf static member wali class ka size 1 (empty class rule).

3. Static member function mein this kyun nahi, aur virtual kyun nahi ho sakta?
Wo kisi object ka nahi hota. Virtual vptr (object) se chalta hai, toh object ke bina meaningless.
4. Static data member ko .cpp mein kyun define karte hain?
Header mein define kiya toh har .cpp mein ek definition: multiple definition error. (C++17 inline ye theek kar deta.)
5. Header mein static int x likhne se kya hota?
Har .cpp ko apni alag copy. Share nahi hoti.
6. Meyers singleton thread-safe kyun?
C++11 guarantee: function-local static ka init ek hi thread karta, baaki wait karte.
7. Static method non-static member kaise access karega?
Seedha nahi (this nahi). Object/pointer/reference argument mein pass karo: static void show(Test& obj) { cout << obj.x; }.
8. Static data member ki definition class ke bahar kyun, aur bhool gaye toh?
Class mein sirf declaration hoti hai; storage ek baar kisi .cpp mein int C::n = 0; se milti hai. Bhoolne pe linker error (undefined reference). C++17 static inline se class ke andar hi ho jaata hai.
9. Static member function ko overload ya function pointer mein de sakte hain?
Overload haan (par same signature ka non-static nahi). Uska address simple function pointer hota hai, kyunki this nahi.

5.1 Rules (rapid fire)

  • Mutual nahi: B ko A ne friend banaya toh B, A ke private dekh sakta, A B ke nahi.
  • Transitive nahi: A ka friend B, B ka friend C, toh C ko A ke private nahi milte ("mere dost ka dost mera dost nahi").
  • Inherit nahi: friend class ki derived class friend nahi hoti. Base ka friend, derived ke naye private members nahi dekhta.
  • Friend member nahi hai: this nahi, object parameter mein lena padta hai, aur public/private mein kahin likho farak nahi.
  • Class ke andar body ke saath likha friend (friend ostream& operator<<(...) { ... }) asal mein class ka member nahi, namespace ka free function hai jo sirf ADL se milta hai (hidden friend).
class B;
class A { int a = 1; friend class B; public: int peekB(B& x); };
class B { int b = 2; friend class C; public: int peekA(A& x) { return x.a; } };   // ✅ B, A ka friend
int A::peekB(B& x) { return x.b; }                     // ❌ mutual nahi
class C { public: int peekA(A& x) { return x.a; } };   // ❌ transitive nahi
error: 'int B::b' is private within this context
error: 'int A::a' is private within this context

Pehla error A::peekB pe (mutual nahi), doosra C::peekA pe (transitive nahi).

5.2 operator<< friend kyun, member kyun nahi

cout << p ka matlab operator<<(cout, p). Member function hota toh left operand apni class ka object hona chahiye (p << cout). cout ostream ka hai, uski class hum badal nahi sakte, toh free function banao. Private data chahiye toh friend kar do:

class Point {
  int x, y;
public:
  Point(int x, int y) : x(x), y(y) {}
  friend ostream& operator<<(ostream& os, const Point& p) {    // member nahi, friend
    return os << "(" << p.x << ", " << p.y << ")";
  }
  friend istream& operator>>(istream& is, Point& p) { return is >> p.x >> p.y; }
};

Point p(3, 4);
cout << p << " " << Point(5, 6) << "\n";        // chaining: har << ostream& wapas karta hai
istringstream in("7 8");
in >> p;
cout << p << "\n";
(3, 4) (5, 6)
(7, 8)

ostream& return karne se chaining chalti hai (cout << a << b). Agar member bana diya:

struct M {
  int v = 1;
  ostream& operator<<(ostream& os) { return os << v; }   // member: left operand M hona chahiye
};

M m;
m << cout;                 // ulta likhna padta hai (aur chaining nahi)
cout << "\n";
1
cout << m;                 // ❌ ye likhna chahte the
error: no match for 'operator<<' (operand types are 'std::ostream' {aka 'std::basic_ostream<char>'} and 'M')

Ulta likhna padta (m << cout), aur cout << m compile hi nahi hota. Yahi operator>> ke liye.

5.3 Symmetric operators: m + 5 aur 5 + m

Member operator+ mein left operand hamesha object hota hai, toh 5 + m nahi chalega. Free (friend) function dono taraf chalata hai:

class Money {
  int rs;
public:
  Money(int r) : rs(r) {}                                                       // int → Money (non-explicit)
  Money operator+(int x) const { return Money(rs + x); }                        // m + 5
  friend Money operator+(int x, const Money& m) { return Money(x + m.rs); }     // 5 + m
  int get() const { return rs; }
};

Money m(10);
printf("%d %d\n", (m + 5).get(), (5 + m).get());
15 15

Sirf member rakha toh:

Money r = 5 + m;           // ❌ left operand 5 hai, member nahi chalega
error: no match for 'operator+' (operand types are 'int' and 'Money')

Thumb rule: =, [], (), -> member hi hone chahiye. <<, >> aur symmetric binary operators (+, == jab left side pe conversion chahiye) non-member/friend.

5.4 Encapsulation todta hai? Kab use na karein?

  • Class khud decide karti hai kisko dena hai (koi bahar se zabardasti nahi le sakta), isliye ye controlled access hai. Par friend jitne zyada, coupling utni zyada.
  • Mat use karo agar public getter se kaam ban jaata. Friend tab, jab operator ya do tightly-coupled classes (container + iterator, class + uska test/builder) ko andar ka data chahiye.
Interview mein

"A friend function or class can access another class's private and protected members, but it is not a member: it has no this, and where I declare it does not matter. Friendship is granted by the class itself, and it is not mutual, not transitive and not inherited. The main use is operators whose left operand is not our class, such as operator<< for ostream, and symmetric binary operators like 5 + money. It does not really break encapsulation because the class chooses its friends, but I use it sparingly because it increases coupling."

1. Friend function member hai kya? this milta?
Nahi. Free function hai, object parameter mein lena padta.
2. A ne B ko friend banaya, B ne C ko. C A ke private dekh sakta?
Nahi: friendship transitive nahi. Aur A bhi B ke private nahi dekh sakta (mutual nahi).
3. operator<< member kyun nahi bana sakte?
Left operand ostream hai, hamari class nahi. Member hota toh obj << cout likhna padta.
4. 5 + obj kaise chalega?
Non-member (friend) operator+(int, const T&). Member mein left operand object hona chahiye.
5. Friend inherit hota?
Nahi. Friend class ki derived class friend nahi banti.
6. Kya friend encapsulation todta hai?
Controlled tareeke se thoda: class khud friend chunti hai. Par sparingly use karo.

6.1 :: scope resolution operator

:: ka matlab "is scope ka naam". Chaar jagah dikhta hai:

  • std::cout, Shapes::x: namespace ka naam.
  • S::x, Base::f(): class ka member (aur class ke bahar member define karte waqt: int S::x = 3;).
  • ::x (aage kuch nahi): global scope. Local variable ne global ko chhupa diya ho toh yahi rasta.
int x = 1;                                         // global
namespace Shapes { int x = 2; void hi() { puts("Shapes::hi"); } }
struct S { static int x; };
int S::x = 3;                                      // S ka x define: S::

int x = 4;                                         // local: baaki sab ko shadow
printf("%d %d %d %d\n", x, ::x, Shapes::x, S::x);
Shapes::hi();
4 1 2 3
Shapes::hi

6.2 Collision, aur using namespace std kyun bura

Namespace ka kaam: alag libraries ke same naam takraayein nahi. std ke saare naam (count, max, distance, list...) using namespace std; se tumhare scope mein aa jaate hain. Tumhara apna naam bhi wahi nikla toh:

int count = 5;                                     // apna global

printf("%d\n", count);                             // apna ya std::count?
error: reference to 'count' is ambiguous
  • Header mein kabhi nahi: jo bhi tumhari header #include karega uske scope mein bhi std ka sab ghus jaata.
  • Behtar: std::cout likho, ya sirf ek naam lao using std::cout;. Chhote .cpp ya practice mein theek hai, interview code mein bhi chalta (poochhe toh ye wajah batao).

6.3 Namespace ke tareeke

namespace Net::Http { int port() { return 80; } }  // C++17: nested ek line mein
namespace Net { int ping() { return 1; } }         // namespace dobara khol ke badha sakte
namespace web = Net::Http;                         // alias

using std::cout;                                   // sirf ek name lao
cout << Net::Http::port() << " " << web::port() << " " << Net::ping() << "\n";
80 80 1
  • Nested: namespace A::B { } (C++17), purane mein namespace A { namespace B { } }.
  • Dobara kholna: alag-alag files mein same namespace ka hissa badha sakte (std aise hi bana). std mein apni cheezein daalna mana hai (undefined behaviour).
  • Alias: namespace fs = std::filesystem; lambe naam chhote karne ko.

6.4 Anonymous namespace = file-level static

namespace { ... } (bina naam) ke andar ka sab sirf us file mein dikhta hai: internal linkage, bilkul file-level static jaisa. Do file mein same naam, koi takraav nahi:

// ---- a.cpp
namespace { int hidden = 5; }       // anonymous namespace: sirf is file mein
int getA() { return hidden; }

// ---- b.cpp
namespace { int hidden = 9; }       // same naam, koi takraav nahi
int getB() { return hidden; }

// ---- main.cpp
#include <cstdio>
int getA(); int getB();
int main() { printf("%d %d\n", getA(), getB()); }
5 9

Plain global int hidden do file mein hota toh multiple definition linker error. C++ mein anonymous namespace static se behtar maana jaata hai kyunki types (class/struct) pe bhi chalta hai, static sirf variable/function pe.

6.5 Bonus: ADL (Argument-Dependent Lookup)

Function call mein arguments ke type ke namespace mein bhi naam dhoondha jaata hai. Isliye:

using std::string;
using std::cout;

string a = "x", b = "y";
swap(a, b);                // std:: nahi likha, phir bhi chala: ADL
cout << a << b << "\n";
yx

string std ka hai, toh swap ko std::swap mil gaya. Ye wahi cheez hai jisse cout << x (operator) kaam karta aur hidden friend milte hain. Poochhe toh ek line mein bolo.

Interview mein

"A namespace groups names so that libraries do not collide; std is the standard library's namespace. using namespace std; brings every standard name into the current scope, which can clash with my own names such as count or max, and in a header it forces that on every file that includes it, so I avoid it there and write std:: or using std::cout;. The :: operator names the scope: ns::name, Class::member, and a leading ::x for the global. An unnamed namespace gives names internal linkage, like file-level static, and also works for types."

1. using namespace std; mein dikkat kya?
Saare std naam scope mein aate, apne naam se takrao (ambiguity). Header mein to sabko force hota.
2. Behtar alternative?
std::cout likhna, ya sirf ek naam: using std::cout;.
3. ::x ka matlab?
Global scope ka x (jab local ne chhupa diya ho).
4. Anonymous namespace kya karta hai, static se kaise behtar?
Internal linkage (sirf us file mein), aur types pe bhi chalta hai.
5. Apni cheez std mein daal sakte?
Nahi: undefined behaviour (kuch template specializations ko chhod ke).
