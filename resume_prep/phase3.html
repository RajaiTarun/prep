Zombie process: kya hai aur mere project mein kaise kaam karta hai pehle se padha hua

Pehle analogy

Ek employee (child) ne kaam khatam kiya aur office chhod diya. Lekin HR ke register (OS ka process table) mein uski entry abhi baaki hai: "naam, aur kaam kaise khatam hua". Kyunki uske manager (parent) ne abhi tak register dekha hi nahi. Jab tak manager ek baar poochta nahi, entry wahin padi rehti hai.

Wo entry hi zombie hai: banda jaa chuka hai, par register mein naam abhi bhi hai.

Technical language mein

  1. Child exit karta hai. OS uski memory, open files sab free kar deta hai.
  2. Lekin OS process table mein ek chhoti entry rakh leta hai: PID + exit status. Kyun? Taaki parent baad mein pooch sake "mera child kaise khatam hua, kya exit code tha?"
  3. Parent wait() / waitpid() call karta hai, to wo entry hat jaati hai. Isse reaping kehte hain.
  4. Child ke exit aur parent ke waitpid() ke beech ka time: child ki state Z (zombie / defunct) hoti hai.
Zombie = child mar chuka hai, par parent ne abhi tak wait() nahi kiya.

Problem kya hai? Ek-do zombies harmless hain. Lekin agar parent kabhi wait na kare (lambe chalne wala shell), to process table ke slots bharte jaate hain, aur ek time pe fork() fail ho jaata hai.

waitpid(-1, ...)-1 = koi bhi child (kisi specific pid ka nahi)
WNOHANGRuko mat. Koi child khatam nahi hua to turant return
Return > 0Ek child reap hua (ye uska pid hai). Loop dobara chalta hai
Return 0Children hain, par abhi koi khatam nahi hua. Loop ruk jaata hai
Return -1Koi child hai hi nahi. Loop ruk jaata hai

WNOHANG kyun zaroori hai? Iske bina waitpid block karta. Agar background job abhi chal raha hai, to shell loop ke upar hi atak jaata, aur background ka matlab hi khatam ho jaata. while loop isliye hai ki ek saath kai finished jobs ek baar mein reap ho jaayein.

Maine ye asli mein chalake verify kiya

Mere shell mein sleep 1 & chalaya aur shell ko prompt pe chhod diya (kuch type nahi kiya). 1-2 second baad ps:

PID    PPID   STAT  COMMAND
14087  14084  ZN    <defunct>        ← sleep ka zombie, parent = shell (14084)

Phir Enter dabaya: zombie gayab ho gaya aur screen par [ 1 ] done sleep 1 aaya.

Honest limitation: sweepCompletedJobs() sirf loop ke top par chalta hai, yaani jab tum Enter dabate ho. Shell getline mein baitha ho to finished background job zombie hi rehta hai aur "done" message bhi tabhi aata hai jab agla command ka loop chale. Mere code mein SIGCHLD handler nahi hai. Production shell (bash) SIGCHLD pe turant reap karta hai. Ye interview mein trade-off ki tarah bol sakte ho: "simple polling approach, signal-safety ke jhanjhat se bachne ke liye".

Interview-ready jawab (30 sec)

"Jab child exit karta hai to OS uski entry process table mein rakhta hai taaki parent exit status le sake. Jab tak parent waitpid nahi karta, wo child zombie rehta hai. Mere shell mein foreground aur pipeline mein parent turant wait karta hai, to zombie nahi bante. Background jobs mein parent wait nahi karta, isliye JobController::sweepCompletedJobs() har loop ke start mein waitpid(-1, WNOHANG) chalata hai. WNOHANG se shell block nahi hota, aur finished jobs reap ho jaate hain."
