wait() aur waitpid() pehle se padha hua

Sabse pehle: ye kaam kya karte hain?

Dono ka kaam ek hi hai: parent ruk ke child ke khatam hone ka wait kare, aur khatam hone par uska zombie reap (entry hata) kare, aur exit status le.

Analogy: manager ne intern ko kaam diya. wait matlab "jab tak koi bhi intern kaam khatam karke report na de, main yahin baitha hoon." waitpid matlab "main sirf Rahul ka wait karunga," ya "dekh ke aaunga, koi khatam hua ho to batao, nahi to main apna kaam karta hoon."

wait()

pid_t wait(int *status);
  • Koi bhi child khatam ho, tab tak block karta hai.
  • Return: jo child khatam hua uska pid.
  • Ye bas waitpid(-1, &status, 0) ka short form hai.
  • Koi control nahi: na ye chuna ja sakta hai ki kiska wait ho, na ye ki block na ho.

waitpid()

pid_t waitpid(pid_t pid, int *status, int options);
ArgumentMatlab
pid > 0Sirf is pid ka wait
pid == -1Koi bhi child (jaise wait)
options = 0Block karo jab tak child khatam na ho
options = WNOHANGRuko mat, turant return
options = WUNTRACEDChild stop ho jaye (Ctrl+Z) tab bhi return karo, sirf exit pe nahi

Return value (teen cases):

  • > 0: us child ka pid, reap ho gaya.
  • 0: (sirf WNOHANG ke saath) children hain par abhi koi khatam nahi hua.
  • -1: error. Jaise ECHILD (koi child hai hi nahi), ya EINTR (signal ne beech mein interrupt kiya).

status ko kaise padhte hain (ye ek packed number hai, seedha mat padho):

MacroMatlab
WIFEXITED(status) / WEXITSTATUS(status)Normal exit hua / exit code kya tha
WIFSIGNALED(status) / WTERMSIG(status)Signal se mara / kaun sa signal
WIFSTOPPED(status)Stop hua (Ctrl+Z), WUNTRACED ke saath
wait = simple, "koi bhi, ruk ke". waitpid = control (kaun, ruk ke ya nahi, stop bhi dekhna hai ya nahi).

Teeno alag options use karte hain, isliye wait() kisi mein fit nahi hota.

Foreground mein wait() ki jagah waitpid(pid) kyun? (important)

Maan lo pehle sleep 2 & (background, child A) chalaya, phir sleep 5 (foreground, child B).

  • Agar wait() hota: 2s par A khatam hota aur wait() A ka pid leke return ho jaata. Shell sochta "foreground khatam", prompt wapas, jabki B abhi chal raha hai. ❌
  • waitpid(B_pid, ...) sirf B ka wait karta hai, A ka nahi. ✅

Isiliye specific pid zaroori hai.

WUNTRACED aur Ctrl+Z (foreground code)

waitpid(pid, &status, WUNTRACED);
if (WIFSTOPPED(status)) cout << "\n[Suspended] PID: " << pid << endl;

Bina WUNTRACED ke, Ctrl+Z se child stop hota par waitpid return nahi karta (kyunki child exit nahi hua), aur shell hang ho jaata. WUNTRACED se wo stop pe bhi return karta hai, aur WIFSTOPPED se pata chalta hai ki ye stop tha, exit nahi.

Pipeline mein order ka sawaal

for (size_t i = 0; i < child_pids.size(); i++) waitpid(child_pids[i], &status, 0);

Saare children pehle hi fork ho chuke hain, to order se wait karna safe hai (deadlock nahi). Agar 3rd child pehle khatam ho jaaye, to wo bas zombie rehta hai jab tak uski baari na aaye, phir turant reap.

Honest limitation: status har jagah le to rahe ho, par exit code kahin use nahi hota: sirf foreground mein WIFSTOPPED check hota hai. Isliye mere shell mein $? (last command ka exit status) nahi hai. Interviewer pooche to: "status mil raha hai, WEXITSTATUS se $? support add karna easy extension hai."

30-sec interview jawab

"wait() koi bhi child khatam hone tak block karta hai. waitpid() zyada control deta hai: specific pid, WNOHANG se non-blocking, aur WUNTRACED se stopped child bhi. Mere foreground mein specific pid pe waitpid hai, kyunki wait() kisi purane background child pe galat return kar sakta tha. Background sweep mein waitpid(-1, WNOHANG) hai taaki shell block na ho. Pipeline mein har stage ke pid pe waitpid hai."

wait() / waitpid(): example se samjho pehle se padha hua

Ye ek real program hai jo maine chalaya, output asli hai. Pichhle section ka simple version.

Setup: ek exam ka example

Parent ek teacher hai. Usne 2 students (children) ko exam diya:

  • Child A: 1 second mein khatam, exit code 11
  • Child B: 3 second mein khatam, exit code 22

Teacher (parent) ko inke papers (exit status) collect karne hain. Teacher ke paas 3 tareeke hain.

Example 1: wait() ("jo pehle khatam ho, wahi do")

for (int i = 0; i < 2; i++) {
    pid_t r = wait(&st);          // koi bhi child khatam ho tab tak ruko
    printf("returned pid=%d, exit code=%d\n", r, WEXITSTATUS(st));
}

Asli output:

[t=0s] child A bana, pid=15893 (sleep 1s, exit code 11)
[t=0s] child B bana, pid=15894 (sleep 3s, exit code 22)
[t=0s] wait() call kiya, ab block...
[t=1s] wait() return -> pid=15893 (A), exit code=11      ← A pehle khatam hua
[t=1s] wait() call kiya, ab block...
[t=3s] wait() return -> pid=15894 (B), exit code=22      ← phir B

Step by step:

  1. t=0: parent ne A aur B banaye, phir wait() call kiya. Parent so gaya (block).
  2. t=1: A khatam hua. OS parent ko jagaata hai. wait() return karta hai A ka pid aur st mein A ka exit code (11).
  3. Parent ne dobara wait() kiya, phir so gaya.
  4. t=3: B khatam hua, wait() ne B ka pid aur code 22 diya.
wait() mein tum chun nahi sakte kiska wait karna hai. Jo pehle khatam hoga, wahi milega.

Example 2: waitpid(B) ("mujhe sirf B chahiye")

pid_t r = waitpid(B, &st, 0);     // sirf B ka wait
// ... uske baad
r = waitpid(A, &st, 0);

Asli output:

[t=0s] waitpid(B) call kiya (sirf B ka wait)
[t=3s] waitpid(B) return -> pid=15912, exit code=22
[t=3s] ab A ko dekhta hoon, A to kab ka khatam (zombie), waitpid(A)
[t=3s] waitpid(A) return -> pid=15911, exit code=11 (turant mila)

Step by step:

  1. t=0: parent ne waitpid(B) kiya, so gaya.
  2. t=1: A khatam ho gaya, par parent nahi jaaga! Kyunki parent ne sirf B ka wait kiya tha. A ab zombie ban gaya (khatam, par kisi ne paper collect nahi kiya).
  3. t=3: B khatam hua, tab parent jaaga, B ka code 22 mila.
  4. Parent ne waitpid(A) kiya. A to pehle se zombie tha, uska exit status OS ke paas rakha tha, to turant mil gaya, bina ruke.

Do badi seekh:

  • waitpid(pid) sirf usi child ke liye jagaata hai.
  • Zombie ka exit status baad mein bhi mil jaata hai. OS yaad rakhta hai.

Mere project mein: execute_foreground bilkul yahi karta hai: apne foreground child ka pid leke waitpid(pid).
